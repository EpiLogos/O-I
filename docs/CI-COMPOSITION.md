# O:I CI composition

O:I contains six independently owned native products. Continuous integration therefore composes native proof; it does not replace native product semantics with a seventh test implementation.

## Native owner law

Each product publishes `.oi/product.json` with its repository identity, build operation, source-verification operation and installed verification operation. Each native repository owns one stable pull-request gate that proves the deterministic merge floor of that product. Rich provider, material, browser or historical acceptance remains owner-native but must not become a second generic pull-request gate.

The six owners are:

- Central
- Actuation
- AIKit
- Software Factory
- Workcell
- Quaternal Logic

No native owner is a permanent CI exception. Active research branches remain valid development candidates, but accepted current product state is represented by the owner main selected in O:I's current source cut.

## O:I composition law

O:I owns:

1. the exact six-product source selection in `suite/mainline.json` / `surfaces.json`;
2. execution of each selected owner's native `.oi/product.json` build and source-verification contract;
3. cross-product compatibility and whole-suite proving that no single native owner can establish alone;
4. exact receipts naming product, repository, revision, owner contract and result;
5. the distinction between current source composition and the historical pre-local artifact manifest.

`suite/manifest.json` is immutable historical build evidence. It is not current CI configuration.

## Cadence

```text
native edit
    → owner quick verifier
    → one owner PR gate
    → accepted owner main
    → owner local rich acceptance where applicable
    → O:I weekly/on-demand exact-source verification for all six owners
    → O:I cross-product / Development Field proving
    → Suite / Composition receipts
```

Checks that read a sibling repository belong in a cross-product office, not in every owner pull request. Superseded PR heads should cancel. Heavy acceptance is retained at the evidence level that can actually prove it rather than being run indiscriminately because a broad source directory changed.

## Quaternal Logic convergence

The QL/Epi programme was deliberately excluded from O:I #97 live-main convergence while its computational substrate was moving. That was a temporary development exception, not a different product law. The convergence carried by QL-MEF PR #194 and its companion O:I change retires that exception:

- QL has one protected PR gate;
- its local K8/K9/kernel evidence remains native acceptance;
- sibling-owner QL proofs run under its weekly/on-demand cross-product coordinator;
- O:I verifies QL through the same native lifecycle contract as the other five products;
- `quaternal-logic` is present in the same six-product current-source matrix.

## Agentic continuation

Factory may correlate a Run/workflow unit with these verification receipts and return failures to the owning product. AIKit may resolve the smallest sufficient repair context and practice; Actuation may admit bounded repair authority. Those are consumers of the CI field. They do not create another CI registry or change the ownership above.
