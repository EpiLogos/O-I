## 1. Host claim

```text
SIX M′ DEPTHS — 4+2
  epi.deep.m0
  epi.deep.m1
  epi.deep.m2
  epi.deep.m3
  epi.deep.m4
  epi.deep.m5

  epi.cosmic.123     = 1 / 2 / 3
  epi.personal.450   = 4 / 5 / 0
```

The eightfold remains canonical.

The desktop does **not** embody the six deep products symmetrically.

```text
M0 / Anuttara
  normally implicit as ground / source / relation / Knowledge

M1 / Paramaśiva
M2 / Paraśakti
M3 / Mahāmāyā
M4 / Nara
  principal foreground deep instruments

M5 / Epii
  normally implicit as articulation / Agency / editing / explanation / return
```

M0′ and M5′ remain complete deep products and may be explicitly foregrounded. Their normal application role is also constitutive of the workbench around every other instrument.

O:I hosts this relation. It does not acquire M semantics.

```text
  Projects / files / Ground / Wiki / Knowledge / Surfaces
```

The Epi correction is therefore mostly a matter of **what these primitives mean in combination**, not a request for a new Epi shell.

The desktop's Navigator/Knowledge/Search grammar is the primary ambient place where M0-owned ground becomes usable.

Representative Epi contributions:

- Bimba semantic refs;
- M/M′ coordinates;
- source anchors;
- relation neighbourhoods;
- provenance;
- current event/subject ground;
- related canon/source readings;
- open-related / deep-open Actions.

The relation is:

```text

        ↓

        ↓
Navigator / Search / reading / source reveal
```

A graph database, graph service, Navigator implementation or provider does not become M0 identity.

When the person explicitly enters `epi.deep.m0`, the same refs may be projected as a specialised cartographic/graph/world instrument in Canvas or an alternate native body.

- LOWER/SYSTEM provider diagnostics;
- exact observation/derivation/inference provenance.

### M3′ — Mahāmāyā

Primary body: professional symbolic-genetic clock/transcription instrument.

Host needs:

- Canvas or alternate-native body;

Host needs:

- no Explore projection from local addressability.

## 6. Workspace tabs are the experienced unit of deep work

The user should be able to arrange the desktop naturally:

```text
[Personal / journal] [M1 played QL] [M3 clock] [M0 cartography]
                      └──────────── split ────────────┘

Epii / Agency sidecar follows the selected semantic subject
Navigator / Knowledge remains available across all workspaces
```

A tab/group is a **workspace presentation unit**. It may retain selected refs and local Surface state.

It is not automatically:

- a new Epi event;
- a new semantic subject;
- a new SessionSpace;
- a new AgentSession.

Several tabs can coexist in one workbench context. If a provider legitimately owns a separate session object, that object must be explicit and native-owned.

This distinction lets a person genuinely work “in M1” and “in M3” simultaneously without creating parallel semantic worlds.

## 7. Inter-instrument coherence is canonical state, not renderer messaging

The desktop must not create a private event bus whose renderer-local payloads become the only way M1–M4 understand one another.

Coherence comes through native Epi/QL relations:

```text
same eventRef / subjectRef
same MCoordinateRefs
Map-derived relation lineage
canonical Actions / Readings
kernel/library operations
source/canon refs
provider observations
privacy / authority / readiness
```

The host may propagate selection/focus as workbench presentation state, but any semantic relation exposed to another instrument must resolve through canonical owner state.

## 9. Common deep-open application service

The host should support the Epi native Actions:

```text
epi.action.deep.open
epi.action.deep.focus
epi.action.deep.return
```

A request carries the existing parent identity and exact M relation.

O:I resolves only application concerns:

- effective registered Surface/body capability;
- authorisation to invoke the native Action;
- target region/tab/split/focus;
- provider availability;
- presentation restoration;
- safe bridge/alternate-native handle.

Epi resolves semantic meaning and returns native product/readiness/provenance.

The resulting Surface may receive an O:I `surfaceRef`; that does not become event/subject identity.

## 10. Heterogeneous body law

The desktop must be capable of hosting or delegating bodies by **capability requirement**, not by historic package name.

Legitimate bodies include:

- document/editor;
- graph/world;
- WebGPU/wgpu/Bevy or another GPU renderer;
- audio/MIDI/native DSP;
- local native application;
- remote/material application;
- specialised symbolic editor;
- TUI;
- declarative reading.

The current implementation may reuse historical Epi code, but Surface registration should describe what the body does and which permissions/providers it needs.

The following are migration/evidence statements, not host ontology:

```text
Graphiti is not M4.
S2 graph-services is not M0.
Theia is not the required Epi shell.
A portal-core file path is not the product identity.
```

## 12. Agent-native acceptance

For every implemented deep Surface, prove both directions:

```text
human
  manipulates/selects native Surface
  → canonical Epi ref / Action

Agent
  receives authorised structured ref
  → same canonical Epi Action
```

The Agent must also be able to request open/focus through native application services without DOM scraping.

Preserve:

```text
selected != disclosed
visible != authorised
Action advertised != Action authorised
local != projected
presentation != semantic identity
```

M4 fails closed.

## 15. Desktop acceptance invariants

1. the eightfold remains six M′ depths plus the two `1/2/3` and `4/5/0` parent worlds;
2. M0/M5 are full deep products but normally ambient ground/return dimensions;
3. M1–M4 are principal foreground deep workspaces;
4. explicit M0/M5 workspaces remain available;
5. tabs/groups/splits do not mint semantic events or automatically mint SessionSpaces;
6. multiple deep Surfaces can coexist over one current event/subject;
7. Navigator/Knowledge does not acquire M0 semantics;
8. AgentSession/editor/Inspector/Command does not acquire M5 semantics;
9. O:I does not recompute C/D/Epi/QL semantics;
10. body requirements are capability-based and heterogeneous;
11. historical package paths remain implementation evidence only;
12. human and Agent address the same refs/Actions;
13. selection and visibility never imply Agent disclosure;
14. protected M4 never becomes Explore-visible by local addressability;
15. current/degraded/deferred readiness is explicit per instrument;
16. richer returned implementation or use evidence revises this document explicitly rather than silently changing the meaning of the eightfold.
