# {O:I} Praxis and Operative Language

**Status:** authored philosophical / product-position clarification  
**Relation:** companion to `docs/positions/FOUNDING-POSITIONS.md`; this document develops an implication already present in the programme rather than replacing the founding positions.  
**Date:** 2026-08-19

## 0. The clarification

Within Epi-Logos, **Logos has never meant theory detached from practice**. It names an articulating relation: a way in which distinctions, reasons, forms, acts and returns become intelligible together.

The AI age makes one consequence of that orientation unusually concrete:

> **A Logos can become operative praxis.**

An articulated distinction can now participate directly in action. A Project can name what it means, why a distinction exists, what evidence would answer it, what operations are legitimate around it, and what kind of return matters; an Agent can then work through those same distinctions as part of its actual operative world.

This does not mean that philosophy should be rewritten as prompts, or that every concept should become a software type. It means that where a Project has already developed meaningful distinctions, there is new value in carrying them coherently from authored language into the procedures, methods, capabilities and return forms through which work is performed.

The resulting relation is useful on both sides:

```text
human articulation
    meaning · value · distinction · judgement
                    ↓
          operative vocabulary
                    ↓
agent praxis
    inquiry · retrieval · action · verification
                    ↓
returned reality
    artifact · claim · evidence · experience
                    ↓
renewed human / project articulation
```

Theory and praxis therefore need not be two disconnected product layers. The authored distinction can become a condition of intelligent action, while action returns evidence capable of refining the distinction.

## 1. Operative vocabulary continuity

O:I should preserve a simple design principle:

> **Where a Project already has a meaningful ontology, procedural language should use that ontology when the relation is real.**

If `Project`, `Focus`, `Claim`, `Evidence`, `ContextSource`, `Action`, `Run`, `Decision`, or a domain-specific Project term is already a real addressable distinction, an Agent should not need to reason in an unrelated prompt vocabulary and then translate back into the software's actual world.

The valuable continuity is:

```text
authored / recognised language
        ↓
project ontology and semantic knowledge
        ↓
Skills and Methods
        ↓
actual Actions / ContextSources / Capabilities
        ↓
Claims / Evidence / Artifacts / experience
```

This is not a licence to saturate ordinary work with system jargon. A term should enter operative language because the relation it names is useful to the act, not because the ontology contains it.

The opposite failure is semantic drift:

```text
human language
  → documentation synonym
  → prompt synonym
  → Agent-invented category
  → tool/API category
  → implementation type
```

Every unnecessary translation is an opportunity to preserve the noun while losing the reason for the distinction.

## 2. Praxis as a constituent of Objective Internality

The founding positions describe Objective Internality as the objectively inspectable structures through which an operative interior can be constituted. Praxis belongs in that field.

A person's or Agent's operative world can contain not only knowledge and powers but developed ways of using them:

```text
Ground
Governance
Project / Focus
ContextSources
Capabilities / Actions
Skills
Methods
SkillSets
Profiles
model / harness / runtime conditions
history of use and returned evidence
```

A Skill is therefore not merely a prompt file. It is one possible durable form of **organised intelligent praxis**: a reusable way of inquiring, judging, transforming, verifying or returning.

A Method is the contextual connective tissue around praxis. It can relate Skills, Actions, ContextSources, scoped usage additions and return expectations around a purpose or Focus without copying or mutating the underlying Skills.

A SkillSet is a selectable repertoire: the praxis made available or projected to an actor. It is not itself a workflow engine.

These distinctions allow a person's working world to develop a craft without requiring every act to be re-described from first principles.

## 3. Personal and Project praxis are recursively related

Central and ProjectCentral give this a natural authored shape.

A person may develop cross-project Ground, governance, Skills and Methods. A Project can then specialise that foundation through its own Ground, ontology, governance, Skills and Methods.

```text
personal Ground / governance / praxis
                 ↓
             Project
                 ↓
Project Ground / ontology / governance / praxis
                 ↓
      situated Context / Focus
                 ↓
                act
```

The Project is not a blank runtime container. It is a differentiated local whole which can inherit useful personal practice while introducing its own vocabulary, constraints, purposes and methods.

Conversely, Project experience can return something genuinely reusable. A repeated Project-local adaptation may become a Method; a stable atomic procedure may become a Skill; a useful family may become a SkillSet; a failed practice may be removed rather than sedimented into permanent instruction.

The source/return distinction remains essential. Repeated Agent behaviour does not automatically become human-authored praxis. Returned reality proposes, pressures and informs; recognition determines what is retained.

## 4. Minimal, median and maximal practice worlds

O:I's commitment to heterogeneous existing worlds does not imply indifference among all possible arrangements.

A minimal AIKit relation can work with somebody's existing files, harnesses, Skills and conventions. That world is real and should remain usable without adopting the rest of O:I.

O:I can nevertheless offer a more developed **median** configuration: an optional first-party praxis foundation combining native Project understanding, Wayfinding, documentation and ontology craft, capability mapping, Skill/Method composition, verification, agent/harness bootstrap and selected external craft where it has been deliberately adopted.

A maximal configuration may go further into Factory Runs, multi-Agent composition, material Workcells, formal QL/MEF refraction and shared-world publication.

The governing principle is:

> **Openness means preserving the possibility space, not pretending every point in it is equally developed for every purpose.**

O:I may develop and recommend stronger native practices while retaining the ability to describe, compare and interoperate with different ones.

This is important both personally and collectively. A person can cultivate a highly particular working optimum; a community can also discover practices which become broadly useful. The personal and transpersonal registers are not competitors. Each can return evidence to the other without requiring uniformity.

## 5. QL and capability matrices

The full O:I / Factory system is structurally informed by Quaternal Logic even when ordinary operation does not require QL vocabulary.

Capability matrices are one practical place where that structural inheritance becomes useful. Skills, Methods, Actions and ContextSources can be related to the kinds of work for which they are suited, including developmental position, use type, required model/harness/material conditions and observed fitness.

QL alignment should therefore help answer questions such as:

```text
What kind of act is this?
Which capabilities and praxis are germane here?
Which relations are absent or overrepresented?
What changed when the model, harness, Method or SkillSet changed?
What returned at Application / Recursion that should revise the next Ground?
```

This does not require translating every Skill into a QL object or making a live QL provider mandatory. The architecture can be QL-shaped while the everyday vocabulary remains native to the Project and act.

## 6. Factory as praxis return and research infrastructure

Once praxis is named and attributable, the Software Factory can study more than whether a model produced acceptable code.

A Run can retain relations among:

```text
human / Project intention
Project + Focus
Agent / Agency
Method
Skill / SkillSet
ContextSources / Actions
model / harness / material conditions
implementation and tests
Claims / Evidence
human Recognition / user-experience return
```

This makes practical questions experimentally available:

- whether a Method remains useful across models or harnesses;
- whether a Project-specific overlay should become a reusable Method or Skill;
- whether a Skill improves implementation while degrading product understanding;
- whether a capability-matrix prediction matches observed use;
- whether a changed working arrangement reduces or increases the human burden of supervision;
- whether returned experience should revise a Project Method, governance, documentation or founding position.

The research object is not merely the Skill text. It is **praxis in a situated world**.

This makes the Epi-Logos meaning of return technologically concrete: an articulated form enters practice; practice encounters reality; reality returns a difference; the form can then be recognised, refined, rejected or developed.

## 7. Shared praxis without collapse

Skills, Methods and SkillSets are also legitimate local-world resources for selective Projection.

A person may keep praxis private, publish it, share it with a bounded field, rebound an external Skill while retaining provenance, or expose a Method which composes several independently owned Skills without copying them.

Explore can therefore become a place where praxis is encountered alongside other projected knowledge and world material:

```text
local Skill / Method / SkillSet
          ↓ explicit Projection
       SharedField / Explore
          ↓
inspect · discuss · compose · rebound · adapt
          ↓
another differentiated local world
```

The source/projection distinction remains unchanged. Publication does not transfer canonical authorship, and adaptation does not erase upstream provenance.

The broader proposition is the same one that governs Objective Co-Internality: useful common forms can emerge through relation among differentiated worlds without requiring those worlds to collapse into one canonical interior.
