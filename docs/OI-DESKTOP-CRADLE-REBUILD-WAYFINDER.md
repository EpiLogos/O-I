## 0. Destination

One act: open the cradle. It opens to **austere rest** — agency field left,
canvas centre, writing as the main human act. Nothing else on screen until
summoned or promoted.

Three verticals — each already operating **by itself** and each consuming and
enacting the underlying product operation:

- **C — the world, written** (S→S0). The person's real world, rooted in
  Central, is navigable; real sources open, edit, save, conflict, and carry
  history through Central owner operations.
- **A — the encounter** (S→S1 via S→S2). Real agents — streaming, addressable,
  interruptible — through AIKit actuation over real harnesses (claude, codex via
  ACP). O:I mounts the effective Surface; it does not manufacture uniform
  capabilities.
- **K — what is known** (S→S2 + S→S0). Search and knowledge gather on what is
  in focus; remember-this writes to chosen destinations with provenance. The
  wiki — project, root, and shared-field projection — is a first-class
  surface and the design-vision centrepiece (D21).

And the everyday loop that binds them:

```text
write in the canvas
  → To: an agent          (address, commission)
  → work returns          (as distinct material, not chat sediment)
  → reconcile into source (owner revisions, conflict-safe)
```

V1 acceptance = all three verticals plus the loop, verified by app
functionality with real metrics (§8). Fog (charted later, not now): Factory
import (S→S2→S3), Workcell material state (S→S4), QL refraction (S→S5),
Lower terminal depth and Nara/Epi retain their native obligations; Gateway
continuity is now explicitly mapped as GW-01–06, not fog.

## 1. Standing laws (enforced on every unit)

1. **Kill product, keep business logic.** `desktop/ui` is removed on the
   rebuild branch. Kernel and other reusable business logic survives only where
   the new design re-derives it — each re-derivation re-proven by a walk, not
   by its tests. The rest is removed, not left unbuilt.
2. **Verify by operation** (`docs/cradle/05-EXECUTION.md §3`):
   > Prose summaries, test output, and contract tests do not establish a UX
   > condition.
   Every unit lands with a **functional walk in the running app** (§8).
   `APP-SPEC §17`: "Visual acceptance is human evidence" — at phase gates the
   owner walks the app; screenshots accompany every receipt. There is no
   separate token/certification theatre: the gate is the app.
3. **The design set wins.** the cradle design set (`docs/cradle/`, files
   01–05), `APP-SPEC` (§4–§8, §11, §13,
   §14, §17), #155 D1–D11 + Buzz specimen, #138, #25,
   `CANONICAL-PRODUCT-FIELD.md`, and the alpha notes are the bar. Design is
   never edited to match code.
4. **No invented ontology.** No desktop chat/session store, no fake filesystem
   tree, no universal event store, no desktop-only Agent/Run/SessionSpace
   semantics. Every surface consumes native owners (APP-SPEC, #155).
5. **Product updates are in scope.** Where the work requires an increment to a
   product (Central, ai-kit, Actuation), that increment is a unit like any
   other — owned by its product, walked in its own harness. This is an obvious
   implication of doing the work, never an escalation.
6. **Model selection is harness-level, never a desktop parameter.** Multi-model
   work is the norm (different models for coding, review, agency). Which model
   acts is stipulated per harness through AIKit harness/profile composition at
   resolution time; the desktop carries no model choice and the AgentProfile
   may honestly report model unset. The cradle renders what resolution
   returned.
7. **Honesty.** Truthful state only — no invented health, no fake loading, no
   simulated streams, unavailable ≠ error (`cradle/04` honesty laws; APP-SPEC
   §14: "professional software, recognisably O:I"; scarce gold).
8. **Files mapped, prompts pithy.** Every unit names its files. Briefs are
   imperative: name the files, the operation, the metric. No hedging, no
   constitution-lecturing.
9. **Owner loop stays live.** Each unit reports a receipt to the ledger; the
   owner is never more than one phase away from a walkable app.
10. **No capability theatre.** Every region of the app renders a real
    operation's real result, or live inference arriving from a real session.
    A region that cannot name its owner operation (or the session producing
    into it) does not ship. The app is "not a larger dashboard" (APP-SPEC):
    capabilities are made usable, never displayed as reports of themselves.
11. **Tokens precede components; the host themes.** The design-token contract
    (U0.5) locks before any vertical component is built. Every component
    consumes `packages/oi-design-system` tokens — no raw values. Composable
    and agent-native bodies (contributions, rich surfaces) are themed by the
    host through provided chrome/context; they never self-chrome, so anything
    entering the app speaks the house visual language.
12. **The OS feel.** S is a functional OS with a built-in canvas and window
    management: tabs as Surface bindings, split/tiling/move/restore, and
    right-click context menus as the primary grammar for complex object
    interactions. Austere rest governs what is on screen; the OS grammar
    governs how what appears is manipulated. The context menu is the
    canonical-Actions disclosure UI — right-click a ref, see the Actions its
    owner discloses, invoke crosses the authority seam (D15). This known,
    high-quality pattern family is the deliberate floor: the app base is
    usually where AI desktop development fails, so it is built first-class,
    before verticals (U0.3b).
13. **Git discipline — one line, one gate, retired branches.** (owner ruling
    2026-09-05, after the branch/worktree sprawl audit; enforced by the
    skill's git ground check.)
    - **One phase branch.** Each phase opens one branch `cradle-<phase>` cut
      from `main`. Units execute only there. No side branches per unit, no
      stacked branches.
    - **Implementers stay on the phase branch.** The orchestrator lands it at
      the phase gate once the stated walk and acceptance checks pass, then
      retires the merged branch and clean worktree. A gate never ends with
      accepted `main` ahead of origin. A new owner ruling is needed only for
      a consequential judgement not settled by the commissioned phase.
    - **Sync before each unit.** The orchestrator fetches all repos before
      briefing a unit. An unpublished, exclusively owned phase branch may be
      rebased if `main` moved; once published, update it without rewriting
      shared history or use the repository's merge queue. The
      brief pins each product repo (Central, ai-kit, …) at the exact commit
      the unit builds against — parallel product work stays current by
      pinning, never by guessing.
    - **No worktrees on the execution line.** `git worktree` is forbidden
      for O:I execution units (it produced the 4617e7a contamination and the
      ai-kit `worktree-agent-*` leftover). In product repos a worktree is
      allowed only for a genuinely parallel build, is never stacked on an
      execution branch, and is removed before the unit's receipt.
    - **Product repos follow the same gate law.** Central/ai-kit increments
      land on their `main` (owner-walked in their own harness), are pushed
      at the gate, and their O:I-facing integrations reference the commit.

## 2. Organising ontology — the capability matrix

The canonical field defines positions 0–5, conjugate faces `H_i`/`A_i`, the
144-relation field, dyadic harmonics D1–D3/O1–O3/C1–C3, and the two triads
(1→2→3 agency-into-expression; 4→5→0 difference-into-ground). Same-position
conjugation `J_i : H_i ↔ A_i` — "one semantic field inhabited from both
conjugate directions" — is the suite's first integration test.

**The cradle's role in this grammar:** S is the composition surface of the
field. Its kernel (stable refs, one global focus, ordered events) is what lets
one semantic object be presented to both faces at once — the cradle *enacts*
`J_i` for every position it mounts, and reaches owners only through their
native operations. Every capability below is stated as a functional sentence —
what S can do, in relation to which position, in which mode, and because of
whose operation — so the matrix bakes intent and function into the language
rather than remapping jargon.

### 2.1 The Action seam is the component grammar

Our agent-native approach already centres the design on **Action objects and
refs**. That centre is what makes components buildable "in the right vein":

```text
a component  =  a stable Ref
             +  the subject's presentable state (owner read model)
             +  the canonical Actions the owner discloses for it
             +  invocation that crosses the authority seam at commit time
```

A component never re-implements an operation, never guesses a shell command,
never invents an Action. Invoking forwards the canonical ActionRef to its
native owner and preserves the real authority result (O:I skill law: *Skill
explains procedure, Capability says available, the native Action/authority seam
decides whether it may actually happen*). The Buzz specimen's frontend lesson
is the same vein: authorised navigation/invocation at commit time.

**Integration with the composability system** (APP-SPEC §11, verbatim chain):

```text
native product/domain
    owns resource / application service / Reading / Action / Surface
        ↓
AIKit Component/Surface composition where applicable
        ↓
O:I package/registration envelope where packaged
        ↓
O:I effective contribution field
        ↓
Navigator | Canvas | Sidecar | Inspector | Lower | System | Command
```

A component built on the Action seam composes by construction: an Action is
what a contribution exposes, so a ref+Actions component slots into any region
the contribution field routes it to. The distinction laws hold everywhere:

```text
Package != Component != Surface != Action != semantic resource
Surface available != active          active != authorised
visible != trusted                   selected != disclosed to Agent
installed != target loaded           provider present != healthy
```

And the inverse guard is APP-SPEC §13 (Surface accounting): every real
human-facing capability of the six products gets a region disposition — nothing
real becomes invisible by accident. No capability theatre in either direction:
no panel that reports capabilities instead of exercising them, and no real
capability left region-less.

### 2.3 Where the system is classical, and where inference actually happens

The failure mode this map forbids: a demo UI covered in panels that report
capabilities, with neither real code underneath nor intended inference space.

**Classical software (deterministic, specified, walk-tested) — most of S:**

- the kernel: ordered event seam, one focus model, ref grammar, two state
  layers, CAS write path;
- navigator projections from owner read models; aperture result lists;
- the transcript's interaction state machine (Buzz lessons), addressing
  parser, keyboard/pointer parity;
- bridge, region placement, layout, focus, drag/split — application mechanics
  (APP-SPEC §11: these are not new semantic identities).

**Agentic activity (real inference, real sessions) — narrow and named:**

- inside agent sessions: everything the harness produces — streaming turns,
  tool use, permission-gated actions (U2.1–U2.6);
- returned material: an agent's flow edit arrives as an owner revision, not as
  UI decoration (U4.2);
- `Contemplate`-class acts: explicit, preflighted, never auto-invoked
  (waypoint W1.4).

Nothing else infers. No panel "powered by AI" as ornament; if a surface region
is not rendering an owner operation's result and is not receiving live session
output, it is not built (law 10).
