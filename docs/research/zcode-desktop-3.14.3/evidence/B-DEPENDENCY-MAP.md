# Dependency map — cradle ↔ oi-design-system, and the cradle's suite placement

## 1. How the cradle consumes the design system

**Mechanism: npm `file:` dependency, consumed through the package's `exports` map.**

- Declaration: `/Users/admin/Central/Work/O-I/desktop/cradle/package.json` line 37 —
  `"@epilogos/oi-design-system": "file:../../packages/oi-design-system"`. Not a workspace
  (`npm workspaces`/`pnpm-workspace.yaml` does not exist at either root); npm materialises the
  package into `cradle/node_modules/@epilogos/oi-design-system` (a symlink or copy per npm
  version — `cradle/package-lock.json` records it). The design system has its *own*
  `node_modules` for checks only and no build step — it ships raw `.css`/`.mjs` consumed
  directly by Vite.
- Public surface: `ds/package.json` `"exports"` — `./tokens.css`, `./desktop.css`,
  `./search.css`, `./point-cloud.css`, `./expression.css`, `./techne.css`, `./assets/*.svg`,
  `./loading`, `./expression`, `./techne-theme`, `./techne-surface-lifecycle`,
  `./themes/themes.css`, `./themes/index`, `./themes/convert`,
  `./point-cloud/config`, `./point-cloud/presets`, `./expressions-engine/*`. Peer dep
  `three >= 0.160` (the engine's only runtime dependency).

**CSS (import order matters):** `cradle/src/main.tsx` lines 3–7:
```ts
import "@epilogos/oi-design-system/tokens.css";
import "@epilogos/oi-design-system/desktop.css";
// The theme library rides after the house tokens: same specificity, later
// order, so a selected theme's overrides win the cascade.
import "@epilogos/oi-design-system/themes/themes.css";
import "./rest.css";
import "./cradle.css";
```
The host body carries `class="oi-desktop"` (`cradle/index.html` line 8); dark/theme-library
selection are body attributes `data-theme="dark"` / `data-oi-theme="<id>"`, resolved **before
first paint** by the inline script in `index.html` (lines 11–33) from localStorage
`oi-cradle.visuals.v1`. Imported custom themes are injected as a generated `<style
id="oi-custom-themes">` block by `cradle/src/visuals/customThemes.ts#ensureCustomThemeStyles`,
with values validated against `themes/import-rules.json` roles.

**JS modules (typed imports by export path):**
- `cradle/src/workspace/settings/VisualsView.tsx` — `PRESETS` and `CONTROL_SCHEMA` from
  `@epilogos/oi-design-system/point-cloud/presets` and `/point-cloud/config`; `THEMES` from
  `@epilogos/oi-design-system/themes/index`.
- `cradle/src/visuals/customThemes.ts` — `parseJsonc, convertTheme, themeVariables,
  uniqueThemeId, guessAppearance, themeImportRules` from
  `@epilogos/oi-design-system/themes/convert`.
- `cradle/src/visuals/ParticleExpression.tsx` (via `Loading`/`Expression` in
  `cradle/src/shared/`) — `loading.mjs` / `expression.mjs`; the expression engine loads lazily
  through `cradle/src/stage/oi-expressions-engine.d.ts` + `src/expressions/hostedApp.ts`.
- Ambient types mirrored locally: `cradle/src/shared/oi-expression-types.d.ts`,
  `oi-loading-types.d.ts`, `oi-point-cloud-types.d.ts`, and
  `cradle/src/stage/oi-expressions-engine.d.ts`.

**Vite glue** (`cradle/vite.config.ts`):
- `resolve.alias`: `three` → the *app's* `node_modules/three`, because the design-system
  package "has no node_modules of its own" (comment lines 24–26) — the peer dependency is
  resolved from the consumer.
- `server.fs.allow: ["../.."]` so dev can serve design-system assets (the loading mark) from
  outside the app root (comment lines 34–39).
- `build.rollupOptions.manualChunks`: `three` → chunk `three`; anything under
  `/expressions-engine/` → chunk `expressions-engine` — both kept off the startup path
  (comment lines 44–50).

**Enforcement / hygiene:**
- `ds/checks/verify.mjs` enforces the "consumers use `var(--oi-*)` only" law for the cradle
  (`ds/README.md`, "The law"); `ds/checks/techne.mjs`, `verify:browser` cover the Technè
  language; package tests `node --test tests/**/*.test.mjs` (theme conversion, lifecycle).
- Generated surfaces are never hand-edited: `themes/themes.css` + `themes/index.mjs` are
  "Generated by scripts/build-themes.mjs from themes/upstream/ — do not edit; rerun the
  script" (file headers), and `cradle/src/contributions/generated.ts` +
  `registered-kinds.mjs` come from the "oi contribution compile-registry".

**What the cradle does NOT do:** no CSS copy into the repo, no PostCSS plugin, no Tailwind
(the separate `expressions-app/` vendored application does use Tailwind 4 + BlockNote and is
its own self-contained build — `expressions-app/package.json` "Self-contained: its own install
and build"; it is embedded as static files under `dist/expressions` by the Vite plugin and
served in a frame, not styled by the house system).

## 2. Build pipeline (end to end)

1. `npm run predev` / `prebuild` (cradle) → `build:expressions`
   (`scripts/ensure-expressions-app.mjs` + `npm --prefix expressions-app run build`) and
   `documents/build-personal.mjs`.
2. `npm run build` → `tsc --noEmit && vite build`; the inline Vite plugin re-ensures the
   expressions app at `buildStart` and copies `expressions-app/dist` → `dist/expressions` at
   `writeBundle` (a direct `vite build` still works — comment lines 12–16).
3. Tauri: `cradle/src-tauri/tauri.conf.json` — `beforeBuildCommand: "npm run build"`,
   `frontendDist: "../dist"`, bundle target `appimage`, bundled resource
   `../../../shared-field/dist-client/` → `shared-field/` (the hosted-field client the kernel
   spawns). Dev: `beforeDevCommand: "npm run dev"`, devUrl `http://localhost:1421`.
4. Distribution: `cradle/package-bundle.sh` wraps the Tauri payload into
   `oi-cradle-<version>-<target>.tar.gz` + sha256 + `.asset.json` (schema
   `oi.desktop-bundle/v1`, footprint from `desktop/install-footprint.json`) — the artifact the
   `oi desktop install` lifecycle consumes; built per-host (linux x86_64 CI, darwin arm64).
5. Kernel: `cradle/kernel/` is the Rust kernel crate (its own `Cargo.toml`, tests under
   `kernel/tests/`); `cradle/src-tauri/` is the thin Tauri shell (commands `kernel_op`,
   `kernel_event_log`, `decision_episode_authorise`, terminal/browser/window commands) that
   links the kernel. Capability/permission files gate every command
   (`src-tauri/capabilities/main-window.json`, `src-tauri/permissions/autogenerated/*.toml`).

## 3. Suite placement of the cradle

From `/Users/admin/Central/Work/O-I/surfaces.json` (schema 1, verified 2026-09-14):
the O-I repo registers six sibling products as **native CLI surfaces** — `central` (ctrl),
`actuation`, `ai-kit` (aikit), `software-factory` (factory), `workcell`,
`quaternal-logic` (ql) — each with install pins and verification commands
(`capabilities --json` / `doctor` / `verify`). The desktop cradle is **O:I's own desktop
shell** (not one of the six): it hosts those owners' capabilities through contributions
(factory surface owned by `software-factory`, automations surface owned by `ai-kit`) and
reads owner state through the kernel's delegation to Central Actions.

From `/Users/admin/Central/Work/O-I/suite/desktop-projection.json`
(`oi.desktop-projection/v1`, standing `architecture-contract`): the desktop is projected as
regions — `0` "World navigator" (files, projects, chats/files/wiki modes), `/` "Canvas"
(pane-local tabs, tiling, subdivisions, popouts), `1` "Context and agency" (active-subject
activity and agent encounter) — and every desktop operation is routed to a native owner
(e.g. `desktop.files.list` → `oi central --json action run central.files.list`, implemented
in `desktop/cradle/kernel/src/files.rs#list`, `native_owner: "S0"`). The cradle therefore
adds no semantics of its own: layout/presentation is desktop-owned; meaning is always a
native owner read.

Other desktop siblings: `/Users/admin/Central/Work/O-I/desktop/` holds only `README.md`,
`cradle/`, `install-footprint.json`.

## 4. Conventions an adopted pattern must follow

- Tokens: `--oi-*` only; new roles go in `ds/tokens.css` under a `/* ===== section ===== */`
  marker with a dark re-grounding in `.oi-desktop[data-theme="dark"]`; theme-convertible
  colour roles must be added to `ds/themes/import-rules.json` and re-grounded in generated
  themes by the build script.
- Component chrome: shared primitives in `ds/desktop.css`; surface-specific CSS colocated
  (`<surface>.css`) beside its component, importing only tokens.
- IPC: every new native operation is a `KernelOp` variant in `cradle/src/kernel/types.ts` +
  `kernel/src/*.rs` handler + Tauri permission toml + capability entry; renderer reads go
  through `kernelOp` (`cradle/src/kernel/bridge.ts`).
- New mounted surfaces: `contribution.json` manifest (schema
  `oi.native-source-contribution/v1`, `entry_sha256`) + `descriptor.tsx` mount export +
  regeneration of `src/contributions/generated.ts` / `registered-kinds.mjs`.
- Persistence: presentation state in `localStorage` under `oi-cradle.*` keys with the
  workspace book's journal/checkpoint pattern; authority state is kernel-owned, never
  renderer-owned (brief law; `src/visuals/customThemes.ts` header is the model).
