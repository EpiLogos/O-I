# Stories: keep working, with better help

**Standing:** source-grounded campaign design, not implemented or tested status.  
**Campaign:** [existing #65 Wayfinder](EXISTING-WORK-CAMPAIGN.md). [Technical participation profile](STORY-PARTICIPATION-PROFILE.md) · [operator protocol](LOCAL-CAMPAIGN-PROTOCOL.md).

The question throughout is what somebody can actually do with their existing work. An Agent's context, discovery, judgment and execution are part of each story, not a second list of tools. The technical IDs below allow exact linking; the human-facing wording should remain ordinary language.

Each section is a parent UX record; rows are child UX records with stable `ux.oi.*` identities. Each child inherits its parent's cited purpose, scope and bindings and narrows them with its actual conditions. A local packet resolves exact sources, Skills, operations, providers and evidence before execution. These tables do not assert that all the bindings are already runnable. Every real step requiring a different permission, state transition or recovery case remains a distinct acceptance obligation.

The final result column always includes what must remain unchanged. Branches are required variants when their condition applies, not optional anecdotes. Subjective human assessment stays separate from what a computer-use Agent observes. The examples supply ordinary tasks; the selected real task should vary so a fixed-answer fixture cannot pass the feature.

## Completion and expansion rule
