# {O:I} Product Surfaces

{O:I} is easiest to enter by need rather than by repository name.

The six surfaces are centres of responsibility, not mandatory stages in one runtime pipeline. A person can use only the surfaces they need, and each product remains independently useful outside {O:I}.

## Persistent personal ground — Central

A useful agentic system needs somewhere durable to stand. Central gives the user a personal working ground for human-authored Control, ordinary Work, machine intent, recovery, and the stable Actions/Connectors that operate those concerns.

The native command is `ctrl`; in a composed installation the transparent alias is `oi ctrl ...`.

Central now publishes the simple Cargo source-install contract needed by composition: install `ctrl` from its Rust package, initialize the native root, and inspect it through structured doctor and Action listing. O:I can register an already compatible `ctrl` or follow that exact native contract at its pinned tested revision. It never copies Central configuration into O:I state.

`Work` remains ordinary filesystem material. Central does not require a Central-specific Project format, so O:I migration does not depend on a fictional project-adoption Action.

## Agent actuation — Actuation

Actuation owns Agency, WorldBinding, RootScope, Metagency, Determination and Return authority. The native command is `actuation`, exposed transparently as `oi actuation ...` when installed. Actuation is its own centre, owned by `EpiLogos/Actuation`.

## Capability and context resolution — AIKit

AIKit resolves skills, tools, Actions, profiles, sessions, harnesses, models, and context at the agentic use level. The native command is `aikit`, exposed transparently as `oi aikit ...` or through the compatibility alias `oi kit ...` when installed.

## Developmental agency — Software Factory

The Software Factory owns durable developmental objects and process such as Projects, Runs, Run Maps, Agents, Agencies, Artifacts, Claims, Evidence, Decisions, and Candidates. Its owner repository is `EpiLogos/agent-system-design`. The native command is `factory`, exposed transparently as `oi factory ...` when installed. Software Factory carries `accepted-main-with-active-research-exceptions` standing in `suite/mainline.json`; moving QL-dependent research remains separately owned.

## Material execution — Workcell

Workcell owns semantic execution-demand materialisation into workspaces, runtimes, services, provider bindings, capacity, placement, and material lifecycle. The native command is `workcell`, exposed transparently as `oi workcell ...` when installed. Workcell carries `accepted-main-with-physical-provider-gates` standing in `suite/mainline.json`; reference-machine and private-provider acceptance remains physical #97 evidence.

## Recursive formal intelligence — Quaternal Logic

**Quaternal Logic** is the public name for the recursive formal-intelligence surface implemented in `EpiLogos/QL-MEF`. The native command is `ql`, exposed transparently as `oi ql ...` when installed. Quaternal Logic carries `parallel-native-owner-exception` standing in `suite/mainline.json`; its broader moving research programme remains outside #97 live-main convergence.

## Six-product native command field

All six product centres now publish accepted native CLIs composed into the `oi` namespace. Each is declared `"command_standing": "accepted-main"` in `surfaces.json`.

| Surface | Native executable | `oi` namespace | Compatibility alias |
|---|---|---|---|
| Central | `ctrl` | `oi central` | `oi ctrl` |
| Actuation | `actuation` | `oi actuation` | — |
| AIKit | `aikit` | `oi aikit` | `oi kit` |
| Software Factory | `factory` | `oi factory` | — |
| Workcell | `workcell` | `oi workcell` | `oi workcell` |
| Quaternal Logic | `ql` | `oi ql` | — |

`oi products [--json]` discloses the complete command field. The composition descriptors in `surfaces.json` retain the discovery, native-install, version, documentation, Skill, and compatibility facts O:I needs for handoff.

Source-level command standing is `accepted-main` for all six products. This does not imply physical #97 acceptance. `suite/mainline.json` records the three standing qualifications: Workcell as `accepted-main-with-physical-provider-gates`, Software Factory as `accepted-main-with-active-research-exceptions`, and Quaternal Logic as `parallel-native-owner-exception`.
