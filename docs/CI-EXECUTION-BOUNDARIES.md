# CI execution boundaries

## Ordinary development and exact suite acceptance

Owner-native PR checks prove the proposed owner change. O:I's ordinary Verify,
S0, desktop and other targeted interface lanes retain their unique obligations.
Development Field conformance and seven-owner D use the declared immutable
`tests/development-field/cut.json`. They prove that cut, not every newer owner
head. Do not refresh it on every unrelated edit or claim candidate acceptance
from owner-only checks.

Full exact-cut checks remain automatic for their workflow, runner, specimen or
cut changes and explicitly invokable with workflow_dispatch. The native matrix
still tests all seven owners; none is made optional to make CI green. Advancing
a suite candidate still requires the corresponding native and joined receipts.

## Failure reporting

Prepare precedes native checkout-dependent operations. Dispatch supplies the
executables for activation and independent native integrations. Lifecycle
requires successful activation, not merely a built executable. S3 requires both
the specimen and dispatch. The whole gate continues to reject missing proof.

`ci-stages.json` and the job summary distinguish actual failed operations from
blocked dependent proof. This is diagnostic output, not product acceptance.
There is no retry-to-green or continue-on-error on a product-proof stage.

## Resource discipline

Only superseded PR runs are automatically cancelled. Accepted-main/manual cuts
are not interrupted by that policy. Concurrency groups include workflow and ref,
so one programme cannot cancel an unrelated lane. Native caches target the actual
workspace: O:I cli/, other owners at root. Cache-on-failure retains dependency
work; Cargo still validates source inputs. Different feature graphs do not borrow
an executable's prior checksum: immutable binary consumers finish before native
bridge tests can rebuild it.

## Retained coverage

The existing S0 workflow is deliberately retained: it covers current cli/,
schemas/, packages/ and suite configuration, unlike the pinned-cut runner.
The new `test_ci_execution.py` checks that this distinction stays operative.
Historical source receipts are not current executable-selection authority, and
P/M/H remain separate from these repository-executable checks.
