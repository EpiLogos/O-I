## 4. Positive architecture and intact implementation to retain

### One developmental authority, several legitimate owners

Factory owns developmental meaning and its Run/Candidate/Claim/Evidence/Recognition relations. Central owns authored source, Project/world identity and the human temporal/receiving field. AIKit resolves and provisions available context/practice/tools/body/model/session arrangements. Actuation owns realised Agency/WorldBinding, execution authority and Activity/Return. Workcell supplies actual material placement/protection/provider operations. O-I presents those native operations and the selected installed composition. None of these roles is a licence to copy the other's registry into Factory. [F-operator] [Positions]

The native attempt store is a particularly important correct implementation: attempts attach to an already-admitted Run inside the same `FactoryDevelopmentalState`, share its advisory transaction lock and publish with the Run. Replay is keyed to the command and its digest; source currency is checked; contradictory retries do not silently create a new work history. A stale caller cannot overwrite another Run's writer reservation. Keep this design rather than introducing a scheduler database, UI completion store or copied task ledger. [F-store]

`ProjectDevelopmentLedger` is also not a discovered lost-update bug. `FileProjectDevelopmentStore::save` acquires the Run lock, merges existing append-only observations, rejects conflicting reuse of an observation identity, and uses an atomic synced publisher. Its role is a receipt field, not a duplicate Project ontology. [F-ledger]

### Developmental topology and actual boundaries

The workflow source carries semantic units rather than bare executable steps. The orchestration engine stages fork admission, checks shared writers, uses the complete workflow for barriers and retains retry and historical execution identities. Independent-reviewer registration rejects producing executions and requires coverage of relevant producer lineages. Synthesis needs a complete barrier, admitted independent reviewer and contributing artifact/evidence coverage; concatenated worker narratives are not native convergence. These safeguards are positive counter-evidence to a blanket self-certification accusation. [F-workflow] [F-orchestration]

Detached, cancellation requested, owner cancellation, process gone, quiescent, failed, returned and late-result states are not interchangeable. Late results remain associated with the originating execution and subject basis; they do not automatically free a current writer or complete a replacement attempt. Ordinary Return additionally requires a real owner dispatch, the appropriate returned observation, no unresolved owner operation and current verification. FA-003 concerns the narrower asymmetry in late verification, not a proposal to erase late evidence or collapse cancellation into failure. [F-app] [F-runtime] [F-orchestration]

### Effects are not merely receipts

Factory's owner adapters invoke actual executables and a bounded Actuation gateway connection. Workcell's declared `workcell-write-boundary` binary prepares and inspects protection requirements before configuring and running a real bounded process. Timeout, incomplete output and uncertainty are distinct from a successful completed effect. Actuation's gateway requires an admitted controller and invocation policy, writes to the target's actual stream and waits for the correlated Return; it does not turn a requested invocation into a returned result. This proves real implementation paths exist, not that every installed provider/harness supports them. [F-owner] [F-gateway] [WC-boundary] [AC-server]

Factory's task preflight and AIKit's native expected-task handler compare actual task, NOW, working directory, Agent/Agency, source revision/hash and binding conditions. The latter reads the real task disposition instead of accepting an echoed “protected” field. Agency handling uses native Actuation admission and checks source material bytes before placing selected context into the working prompt. Retain exact context and protection checks through replacement/re-entry, including profileless legitimate work. [F-task-dispatch] [AK-task] [AK-agency] [AK-service]

### Evidence, receiving and useful learning

`ArtifactSnapshot` already provides a stronger basis than text receipts: an exact subject/revision/state tuple, bounded selected paths, private captured state, content/permission/membership digesting, double observation and revalidation. It rejects unsupported symlink scope and marks changed artifacts historical. Its comments correctly do not claim an atomic filesystem lock, artifact quality or whole-Run closure. ### FA-003 — Late-result incorporation can reuse an earlier pass after a later failed/unknown verification

**Standing / priority / confidence:** static-proven discrepancy between admission guards; P1, high confidence in the code path difference. The regression sequence below is proposed, not executed.

**Seam key:** Factory `attempt_application.rs` ordinary `ReturnArtifact` versus `IncorporateLateResult` → `attempt_runtime.rs::has_passing_verification`.

**Activity and authority.** After interruption, a late result is considered for incorporation. #221/#222 and the operator Skill require original provenance, current evidence standing and explicit recovery, rather than making an earlier success erase a later contradiction. [F221] [F222-claims] [F-operator]

**Positive / negative requirement.** Keep late artifacts, originating execution and subject/quiescence checks. Do not accept an obsolete pass solely because it is somewhere in the attempt's verification history. Do not fix this by discarding all late results or requiring an ordinary returned-delivery phase for a legitimately different late-result lifecycle.

**Code.** Ordinary application Return examines `verifications.last()` and explicitly rejects a later Failed/Unknown result. Late incorporation has the current-attempt admission check but not that latest-verification guard. Runtime's `has_passing_verification` accepts any prior covering Passed receipt; the incorporation branch uses it. The orchestration engine's late-result state and subject checks do not supply assessment supersession.
