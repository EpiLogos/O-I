O:I cradle · desktop design

The two sidebars, Factory and Settings, in every state

One design for the left and right sidebars across every mode, the Factory pages (Desk, Run, Tasks, and the object pages Inspect opens), and Settings. Built to be implemented once and tested against. The study renders each state with the desktop's own tokens, using real content from this machine where it exists. Everything is judged by one question: is this good to use?

The seven laws

  1. 1One frame, changing body.The left head (scope, search, create) and foot (Inbox, modes, Settings) never move. Only the body changes with the mode, and in Settings the body is the section list.
  2. 2One conversation, one place.A session appears once, with one composer and one draft. Outside Factory a chat opens in the right panel; in Factory it opens in the centre Tasks view.
  3. 3State lives on the thing.Working, needs-you, unread and failed are marks on the row, avatar or tab. No banners, no trays, and the layout never moves.
  4. 4Status → Preview → Takeover.A dot, then the live tape, then full-screen chat (⌘⌥J). You choose the depth.
  5. 5Inspect opens the object.Its own page: a canvas tab in Base, in place with ← back in the full-page modes, or popped out into a window. Never a drawer, never a right-panel tab.
  6. 6Headers only above real rows.Empty sections take no space. A failed read says so; it never looks like "empty".
  7. 7Nothing reads like a log file.No "returns", no refs or JSON outside Show raw, no scrollbars, no "Situated in…", no fake rosters.

Factory

Desk — the run board

Four columns: Needs you, Active, Queued, Recent. A card shows the owner's state word, a title taken from the commission's purpose (never a run: ref), the next step, one segment per work unit (never a percentage), the agents carrying it, and the project name. Sources are discovered with factory project locate, not typed in. The Desk follows the one scope, where All projects is a scope-menu entry.

Run — Map · Trajectory · Live · Handoff

Map is the meaning: one lane per work unit, forks, gates and convergence, with the frontier outlined and a detail band listing each required check. Trajectory is the DeepSeek-style run log: a lane strip, typed rows joined by call, turn markers and usage stats, all from the real journal. Live shows who carries each leg right now and where. Handoff is what came back, in the owner's order, with Recognise as the primary action.

Tasks and the right panel

Tasks is the conversation at full size. A Run chip appears only when the session really belongs to the run; the join now reads executions and attempts, not just trajectories. The composer's plain "Connect with…" list becomes a connection picker grouped by harness. On the right, Run shows the compact tape, Agents real roster rows (no pasted markdown), and Context the preserved insertion canvas with Factory's slice.

What the real data carries

Claims, candidates, trajectories and token totals in the build view are only written by tests and specimens today. So the pages stand on the run map, work-unit inspection, attempts, telemetry and the conversation journal. The journal carries timestamps, tokens, cache and cost for Pi sessions. Settings

The left body becomes the section list: Status, Harnesses, Models, Credentials, Skills, Profiles, Permissions, Appearance, then Products (one page per owner). The right panel stays collapsed, offering a help chat. Each change goes stage → review → apply → read back. A pending strip appears only while something is staged. One review sheet names each change's effect in plain words (Restart Claude to apply, Next session only). Apply reads the owner back before saying Applied ✓.

Harnesses by name: 4 ready, 11 detected that still need an adapter, 3 not found. Models per harness, with each route marked Usable, Needs a key or Local; Auto keeps its name, and there are 8 ranking policies. Credentials as cards with Verify, Rotate and Revoke, plus a write-only key field that empties after saving. Skills as toggles grouped by source, per scope; these are writable today. Read-only settings show a lock and where they are owned. Missing operations are named in a sentence, never shown as disabled buttons.
