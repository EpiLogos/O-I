# Presentation state — proposed language addendum

Standing: proposal for owner ratification; this file does not amend the rulings
in `packages/oi-design-system/DESKTOP-LANGUAGE.md`. Implementation is commissioned
by Lane B of `desktop-agent-conformance-rectification-2026-09-23-1756.md`.

The desktop's theme selection and imported theme library are desktop-owned
preferences. Importing, selecting, removing and reverting them cross typed
kernel operations, persist under the configured O:I home, and produce ordered
kernel events when they change. Reads and repeated equal selections produce no
effect receipt. The native window appearance follows that same committed state.
Only existing house roles with validated colour values or house shadow values
reach the CSS cascade. A theme file cannot introduce roles or executable CSS.

The workspace arrangement, selected tabs, browser addresses, scroll positions
and picker selection remain presentation-local. They locate a view; they do not
assert current source contents, capability availability, admission or authority.
Unplaced writing and unsent chat input are device drafts. Saving them still
requires the relevant native owner and its revision check. A restored browser
cache cannot authorise an Action or overrule a fresh owner read.

`presentation_read` discloses the kernel-owned appearance and advisory renderer
observations of arrangement and visual controls. Observations name their
standing explicitly, contain no writing or chat bodies, and are not durable
world source. Their renderer identifiers are observation addresses, not
authenticated native window or person identities. An agent using this reading
must keep that distinction in any decision basis.

The browser's prepaint theme cache only avoids a startup flash. The first native
read replaces it before theme controls become usable. An unreadable native
document is a visible failure, not permission to restore browser data as truth.
Historical custom-theme cache bytes are not silently promoted into the native
library; an import remains an explicit operation through validation.

Nara tool-decision records cross a separate kernel recording operation before
the renderer reports or executes them. The original `decided_by` attribution is
retained. Recording a decision does not execute an Action or create authority;
the existing owner dispatch and admission checks remain required. Reusing a
decision reference for different contents is refused.

Verification belongs beside these rules: real store restart and atomic removal,
malformed/CSS-injection refusal, exact event order and idempotence, and native
application interaction. A static architecture check alone does not establish
that the visible experience works.
