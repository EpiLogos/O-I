# Personal Web — Beings, Things and the six initial HTML forms

**Standing:** owner-approved product/design direction, 13 September 2026; detailed implementation choices are attributable engineering elaboration. **Feature:** [#279](https://github.com/EpiLogos/O-I/issues/279), inside desktop #190 and Explore #18. **Installed acceptance:** the existing [#65 experience campaign](../experience/README.md), not a second reinstall programme. This document is the feature companion of [Continuous Work](../OI-DESKTOP-CONTINUOUS-WORK-WAYFINDER.md). A table of requirements is not a completed experience.

## 1. The world someone can make

I can build a personal web with my agents: a home, writing, interests, works, people, projects, occasions and collections. I can organise it through time and relations, craft how each page looks, and choose the parts that others can enter. Someone can encounter my work, follow it to me, discover a shared interest and continue into another world. My private sources and ongoing work are not the price of participating.

**Beings** and **Things** are the exact plural family names. Beings presents a situated presence and opens its world; Things gives a subject or work an intelligible presentation and a place in relation. They join Flow/Dialogue, Day/4+2, Yoshimoto Cube and Epi-Card. Six is the initial repertoire, not the maximum number of templates, a compulsory workflow, or six allowed forms of thought. One-off authored HTML and later user-made templates are legitimate.

This is base O:I experience. Central is the same root meta-project beneath personal and project work. AIKit supplies existing knowledge, context and capability access. O:I owns document experience/composition and shared presentation; the actual native owners retain sources, identities, permissions and operations. Ordinary use does not require M/M′, Epi adoption or a live QL-MEF service. Intrinsic portable Wiki structure remains QL-grounded; optional deeper interpretation and instruments specialise this same world.

## 2. C constitutes the page-world grammar

The owner corrected an earlier merely abstract classification: C can organise the underlying Beings/Things page body itself.

```text
C0  source / originating Being-world
        ↓
C1 Form | C2 Entity | C3 Process | C4 Type/context
        what a page articulates or organises
        ↓
C5  presented expression, available to another encounter
        ↺ explicit Return to its actual ground
```

This is a scoped application of the recovered **C Category family**: C0 Bimba, C1 Form, C2 Entity, C3 Process, C4 Type, C5 Pratibimba. It does not rename that family, identify it with C′/Vāk, or use the experience campaign's C0–C5 stage IDs as page categories. Preserve exact source profile/version and the reason for the mapping.

A Being becomes a Thing *for another*: its chosen expression becomes something another can enter and relate to their own world. The originating subject is not duplicated. C0/C5 express source/presentation relations, **not private/public**; a private presentation can be C5 and a public native world still has a C0 ground. Audience and authority remain separate native facts.

C1–C4 are subject/organisation profiles, not decorative tags. They inform appropriate structures and operations. A page can articulate more than one profile. Rendering-family identity is independent: Flow develops material, Day situates it, Cube unfolds relationships, Card condenses an achieved reading. Do not force six renderer IDs into six exclusive Category slots or infer semantic completeness from visual geometry. Human headings remain native to the subject.

## 4. Authored HTML, source and presentation

An authored HTML page can itself be primary source. A derived HTML account retains its input bases and standing. An audience-scoped Projection is a separately revised presentation. The older statement 'HTML is a renderer' applies to that derived account; it cannot prohibit human authorship in the new carriers.

The initial common binding retains document/template identity and version, native world/subject refs, C profile, source refs and exact revisions, standing, permitted links/asset references and available owner operations. Content, appearance and view state have different jobs. Unknown extension data must survive round trips. A general imported HTML page is not rejected for lacking a proprietary profile, but unsupported structured edits must not silently reinterpret or discard its contents.

An agent can compose the actual document, develop a reading, design imagery/type/motion, and revise it with the person. 'Change the design' must not rewrite an accepted interpretation; 'revise this paragraph' must not discard chosen composition or exact symbol geometry. Preserve separate content/design/asset locks and their source decisions. A full page builder is not a prerequisite: source editing, useful direct controls, agent edits, real preview and reviewable revisions are already an authoring path.

The host owns application chrome, trusted navigation/authority and native controls. **The authored document owns its art direction.** O:I tokens are a default vocabulary, not a command to make every page resemble settings. Explicitly distinguish artwork from the inherited host-theming rule. Arbitrary page script gains no native filesystem, session credential or Action authority. Rich interactions use contained HTML plus a narrow admitted host operation boundary, not remote-module execution inferred from a manifest.

Opening, selecting, folding, flipping and reading have no model/permission effect. Agent requests disclose the selected structured subject and actual source basis, not scraped HTML or the whole private document by default. Creating a file, saving source, exporting a full copy, publishing, receiving a contribution and accepting it into source remain different operations.

## 5. Personal and Work are arrangements of one world

Place **Work / Personal** at the bottom of the existing left sidebar. Work retains the current project/session/task navigation. Personal foregrounds a compact calendar, Today, expandable days/periods and stable Home, pages, Things/collections and People routes. The central home is a real customisable HTML composition, including a gallery, not a seventh required ontology or permanent dashboard.

Calendar grouping uses declared occurrence first, then explicit local creation date where appropriate. Revision time does not move an old occasion to today. Enduring pages may appear on several dates without copied files; no mandatory date folders, private-source migration or forked Central root. A manually arranged collection stays curated; a query-backed section has an inspectable query and refresh policy.

Preserve each arrangement's open surfaces, selected day/project, focus, scroll/caret, pin/follow and graph camera. Switching does not close dirty work, cancel agents or mint another session. Background work remains reachable through the existing attention channel without forcing tool chatter into personal reading. Activity arrangement, world being visited and audience are three independent facts: Personal is not private; Work is not public.

## 6. Wiki, pages, people and graph

Pages are the explorable human face of an intelligent knowledge world, not necessarily a rendered copy of a Wiki. Support deliberate 1:1 page/subject binding, multiple presentations of a subject and pages composing several subjects. Explicit typed links can yield attributable backlinks; agent-proposed semantic relationships remain proposals/derived knowledge until their owner accepts them. A mention is not automatically an interest, endorsement, collaboration or ownership assertion.

From a page, summon its bounded local graph. From a node, show a lightweight preview then open the actual page beside, full-size or in a native popout. Pin a reading or deliberately follow graph selection; preserve back/forward, the origin constellation and native re-docking. Reuse current Surface/window mechanics. Shared/page details do not replace the optional accompanying agent sidebar. Do not continuously run every card/cube as a graph thumbnail or load every world to draw a neighbourhood.

The public Human Participant Root resolves the chosen Beings entrance. People/work/interest neighbourhoods derive from explicitly projected relationships, never indiscriminate private-source scanning. A Thing leads to its actual creator/steward/participant; a shared topic can connect several worlds. Refs persist across collections, editions and transport locators. Contributor, author, publisher, steward and agent participation remain inspectable.

## 7. Shared publication and its actual carrier

```text
native authored source / HTML
    ↔ Wiki relationships and readings
    → selected audience Projection
    → actual hosted HTML/assets + live SharedField state
    → independent encounter / Contribution
    → authorised native Return / new source revision
    → reprojection
```

SpaceTimeDB is the existing first live SharedField path, not the source owner of every page. A serving/bundle path carries actual HTML and assets; large media need not be replicated through database rows. Exact service and asset-provider choices follow the current hosting line. Opening a page does not require access to the private Agency Gateway. Conversely, native remote agent communication does not require public page publication.

**Full portable copy is not filtered publication.** Build the permitted representation from allowed fields/records/assets before serialising it; remove hidden JSON notes, journal, packets, private refs and embedded metadata as well as visual content. Include backlinks, thumbnails, indexes and failure paths in private-sentinel tests. Preserve unknown fields for private authoring; an unknown field in an outward projection must be withheld or explicitly admitted, never automatically forwarded. Arbitrary customised script/content cannot be certified safe for partial publication by deleting a few DOM nodes.

Visitor preview uses actual audience-authorised content and capabilities. A QR resolves an approved public ref or immutable edition, never private credentials; stable live address and immutable edition are distinct. Hashes identify bytes, not authorship, permission or secrecy. Withdraw/revoke/reproject through actual owner operations. Do not promise erasure of an authorised offline export.

Publication hosting can serve an edition while its source workstation is offline. Hosting an editable native world is a separately chosen ownership/placement relation. Never create two writable canonical copies through casual sync. The second machine is a useful later proving topology, not a precondition for repository development or an architectural identity.

### First-cut implementation qualification

Beings/Things reference HTML is generated from the checked-in module on `npm run dev` and `npm run build`, in the existing owner-resolved `desktop/cradle/documents` directory. Only these built-in generated targets are overwritten; user-created instances elsewhere are not. `node documents/build-personal.mjs --check` proves deterministic reproduction. A source checkout without building gets an honest unavailable-file state. Installed asset placement still needs the native delivery receipt; no installation is performed by this commit.

The current reference renderer supports title/subtitle/introduction, text sections, relation-labelled links, two compositional arrangements and paper/ink presentation. In-document editing and **Save HTML copy** are browser operations; native source editing continues through the existing source route. Export includes the complete embedded data, explicitly **not** a sanitised or audience-filtered publication. It never writes source or creates native subjects. First explicit export may allocate portable document identity; merely opening does not.

Private source bodies, exact provenance and extension fields remain unchanged by appearance edits. The reference formatter rejects unsupported structured profiles rather than lossy conversion. It is not the universal renderer for all future custom HTML. Native edited-preview Save, suspend/reentry without draft loss, asset editing, permissions, true catalogue discovery/overrides and generic imported forms remain PW1/PW2/PW4 obligations. Do not certify these from standalone browser tests.
