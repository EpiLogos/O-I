# Expression Field — lived UX and agent-native acceptance

**Standing:** owner-approved UX direction, 14 September 2026. This extends the existing O:I experience campaign; it does not replace the Cradle spine, Personal Web stories, K9/K10 acceptance or SharedField acceptance.

## 1. Governing experience

The person should feel that they are **inside the thing being understood or made**. Information, source, graph, Agent and editing apparatus arise where useful and withdraw without destroying continuity.

The ordinary loop is:

```text
encounter a living Expression
  → focus a Being / Thing / relation
  → inspect or summon source / graph / Agent / Studio
  → understand or act through canonical Actions
  → observe the actual returned difference
  → compose / save / teach / publish / return
  → later re-enter the same subject and lineage
```

The Expression is not a decorative landing page for capabilities. The person can operate the represented world through it.

## 2. Spatial and interaction grammar

**Rest:** the Expression dominates. Persistent UI is restrained and comes from the Expressions workspace/application grammar.

**Summoned depth:** graph/search, source/properties, Agent/Epii, Studio, Activity, Context and evidence appear as overlays/panels/splits/pop-outs over the same subject. No side depth is mandatory merely because the current Expression is Nara or knowledge-rich.

**Focused instrument:** the Expression can become full-screen/maximised. The graph and Agent remain available without being permanently open.

**Embedded:** a smaller Expression can live inside an HTML/WorldPresentation page or ordinary desktop surface, with explicit expand/open/focus.

**Ambient/subtle:** an authorised Expression can act as a small live presentation or Agent/knowledge state cue without becoming hidden automation authority.

Presentation changes never remint the Expression, bound subjects, AgentSession, Wiki subject, M coordinate or Nara occasion.

## 3. Human/Agent parity

A human may select, drag, arrange, edit and invoke through visible controls. An Agent receives the same subjects, scene/entity identities, relation bindings, available operations, parameter state, source revisions and ActionRefs through structured application state.

The Agent never needs DOM/canvas scraping to know what the person selected or to create/edit/deploy an Expression. The human never needs to understand engine internals to ask an Agent to compose one.

Agent operations are inspectable and attributable. A visual change caused by an Agent is linked to the actual application operation/Activity. Ambient animation and autonomous engine motion remain distinguishable from Agent activity.

## 4. Experience stories

### EF01 — Enter an Expression and remain in the world

Start from an existing Expression or an addressable subject with a derived Expression. The field opens as the primary body. Summon Studio, graph and Agent in turn, then dismiss them. The same subject, scene, camera/focus and live state remain.

**Failure:** entering depth replaces the subject, rest requires permanent sidebars, or returning from a pop-out creates another Expression instance without an explicit fork.

### EF02 — Project knowledge into a living local whole

Search or select a source/Wiki/Bimba subject. Project its bounded typed neighbourhood into the Expression Field. Re-centre on a neighbour, return/back, inspect an edge's exact relation/source and open the underlying page/source.

The visual arrangement may use QL constellation/harmonic grammar where supplied, but no relation is invented from geometry.

**Failure:** graph data is copied into an Expression-owned knowledge store; neighbourhoods are fabricated; current source/revision is lost; the whole graph is loaded merely to show one local field.

### EF03 — A coordinate becomes a whole-field page state

Open an M/Bimba coordinate. Its relevant determinant is foregrounded while source, related M dimensions, Nara/Epii and other readings remain available. Open another coordinate and observe a different refraction of the same underlying field.

**Failure:** each M coordinate becomes an isolated app/page taxonomy; a generated visual is treated as the coordinate's canonical truth; authored and derived Expressions are indistinguishable.

### EF04 — Learn through M4.5 / Epii composition

Ask Epii to explain a selected relation. Epii creates or adapts a short pedagogical Expression sequence: source-bearing objects, movement/state transitions, concise optional text and method/evidence disclosure. The person can pause, inspect source, ask a question, reject the reading or continue.

**Failure:** the teaching is only a long chat response; the Agent drives undocumented pixels; source inspection breaks the lesson; rejection is not retained.

### EF05 — Nara as a bound personal Expression

Enter Nara mode over an authorised PersonalFieldState. Seven independently constituted centres become live receiving loci over the same K8 world occasion. Focus one centre and inspect its actual M1/M2/M3→M4 relation. Summon Bimba or Epii only when wanted.

M1 topology, M2 resonance/audio/material and M3 form/clock are focused aspects of the same field. Cymatic resonant stations remain distinct from chakra-centre identity.

**Failure:** hard-coded visual chakra values replace K10 truth; selection retunes without an explicit Action; a second clock/audio/field owner appears; private Personal state enters exported Expression data.

### EF06 — Agent as a Being in the field

Open or project an Agent Being. Its presentation can reflect selected personality/presence, current subject, Activity/attention and available faculties under explicit disclosure. Invoke or converse with the same Agent through the canonical AgentSession.

**Failure:** personality presentation changes authority; animated activity is reported as real action; a visual Agent creates another Agent/session identity.

### EF07 — Author with Studio, then hand work to an Agent

Create or edit an Expression using the current Expressions UI: entities, scenes, toolbelt, Studio, automation and optional text. Ask an Agent to refine one bounded aspect. Inspect the proposed/actual changes and continue editing manually.

**Failure:** Agent edits discard manual scene structure, locks or provenance; manually taking control does not have a clear relation to automation; source/content changes hide inside design changes.

### EF08 — Put an Expression inside a page

Create a Beings/Things or other HTML/WorldPresentation page and insert a live Expression binding. Open it live, view image/video fallback, promote it to the full Expression workspace, then return to the page.

**Failure:** embedding creates a second canonical Expression; page JavaScript gains ambient native Action authority; a fallback is passed off as live state.

### EF09 — Share a projected Expression

Create an audience-scoped Projection of a suitable Expression/WorldPresentation. Another independently authorised world encounters the live or fallback representation, inspects disclosed provenance, forks or contributes, and returns an attributable difference through existing SharedField rules.

**Failure:** raw private Nara/Agent context leaks; publication implies source mutation; unavailable live renderer causes silent loss rather than an explicit fallback.

### EF10 — Recover and continue

Leave an Expression with an active scene, selection, Agent relation or knowledge locus. Re-enter after restart/reload/provider degradation. Recover authored/configuration state and clearly distinguish what live simulation state could or could not be restored. Continue without re-teaching the Agent the subject where native context remains available.

**Failure:** configuration replay pretends to be an exact particle/resonator checkpoint; current sources silently replace historical ones; context loss produces fabricated continuity.

## 5. Agent-native application operations

The first operable floor should expose structured application operations equivalent to:

```text
expression.open / create / fork
expression.subject.bind / unbind
expression.entity.add / remove / focus / update-presentation
expression.relation.bind / update-presentation
expression.knowledge.project-local-whole
expression.layout.apply
expression.scene.create / reorder / activate / compose
expression.domain.bind / follow / release
expression.parameter.set / automate / take-manual-control
expression.capture.image / video
expression.page.embed
expression.save / export
expression.projection.prepare
expression.source.inspect
expression.subject.action.invoke
```

Exact naming follows the existing O:I Action/application grammar. Not every presentation edit needs a canonical cross-product Action identity; draft-local UI mechanics remain application interactions. Consequential domain/source/publication operations route through their actual owner and authority seam.

## 6. Acceptance qualities

**Alive:** different representations respond coherently to real subject/domain state without constant reseed or fake animation. Human assessment decides whether it feels expressive; tests can only prove continuity and ownership.

**Direct:** common acts happen on the field; deeper apparatus appears only when invoked.

**Intelligible:** any meaningful visible state can disclose what subject/source/operation it represents. Decorative motion does not masquerade as evidence.

**Creative:** the person can make genuinely different compositions, pages and pedagogical sequences rather than merely select fixed themes/presets.

**Agent-native:** a fresh capable Agent can discover, inspect, compose and operate Expressions through structured capabilities and Actions without hidden prompt knowledge or DOM scraping.

**Composable:** the same Expression can move between focused desktop use, embedded page, capture/fallback and SharedField projection while native subject identity and authority remain stable.

**Joyful:** the person's attention is primarily on the world, making and discovery—not on managing the architecture. This remains a human UX judgement, not a numerical metric.

## 7. Evidence ladder

Keep these standings separate:

```text
vision / UX specified
contract implemented
native operation technically supported
Agent capability discovered/projected/loaded
controlled operation exercised
real desktop/engine exercised
provider/material path exercised
human assessed
SharedField/two-world assessed
```

A screenshot, static graph, passing registry check, generated page, green headless test or plausible Agent narrative cannot independently close the experience.

## 8. Required negative tests

- unavailable/missing native subject or source;
- stale Wiki/source revision;
- stale domain generation;
- denied Action/authority;
- Agent capability unavailable despite visible UI affordance;
- WebGL/audio/provider loss;
- scene/configuration restoration without exact dynamic checkpoint;
- private subject projected toward a broader audience;
- imported legacy data requiring migration;
- relation/layout source absent;
- Agent operation interrupted or refused;
- concurrent human/Agent editing;
- embedded renderer unavailable and fallback used.

The desired result is graceful, inspectable degradation—not capability theatre and not hidden manual repair.
