# 7 — How a person or fresh Agent should “get into” the system

The entry procedure should feel like orientation into an existing world, not booting a control plane.

## 7.1 Establish the actual world

Determine:

```text
Central root / current Project if any
machine / host / Workcell locus
current managed candidate receipts
available Agency / AgentSession / places
current subject or work if continuing
material/provider degradation
```

Do not manufacture a Project when root work is legitimate. Do not assume a visible pane is the AgentSession or that a running process is current simply because it survived an update.

## 7.2 Read the relevant UX source

Start from the person's actual intended activity, then read only the governing stories/states and domain UX needed for that activity. Do not begin by reading every open issue.

For example:

```text
ordinary writing / direct work
    → Cradle A–K + relevant story/practice

Factory work
    → Factory/Agency + Session Grounding + Cradle G/D/E

Expression encounter
    → Expression World UX + Epi UX spine if installed

Technē/deep research
    → dual-reading lock + instrument UX + same Cradle subject/session states

joined acceptance
    → #65 C0–C5 + selected V/TD/native obligations
```

## 7.3 Resolve, do not manually wire

Use the actual source/Skill/Method/Capability/Action routes. Human Search and structured Agent work share AIKit's typed Resolve field; Epi deepens the same relation through Vāk/C′ when present.

The person should not have to know which repository owns the next call. The lead Agent follows the native owner relation and carries the handoff.

## 7.4 Choose the native performance body from the work

```text
ordinary direct task
    → native Action / direct Agent / familiar harness

creative Expression work
    → Atelier

commissioned developmental difference
    → Factory

material body / room / model service
    → Workcell / provider owner

source / Wiki / knowledge work
    → Central / AIKit / owning source Actions
```

Do not turn everything into Factory merely because Factory now exists. Do not hide a real development change inside an Atelier mutation either.

## 7.5 Let failure become legible work

When reality disagrees:

```text
preserve original episode
→ identify failed relation and owner
→ retain exact UX/source expectation
→ commission bounded repair where necessary
→ produce evidence/candidate
→ re-enter the same activity
→ independent replay
→ Return
```

That is C4. Once self-hosting is functioning, this should increasingly happen from inside O:I itself.

## 7.6 Ask the human at the right time

Human observation can guide development at any time. **Human Recognition is not a premature build gate.** Ask for standing H/EX evidence when the composed experience being evaluated is the one intended to stand, not when a carrier is intentionally only halfway to that experience.

The human's office is then meaningful: use the thing, redirect it, reject it, or recognise it. They are not the build scheduler or missing cross-product message bus.

# 8 — Traffic laws for the final phase

1. **One UX spine.** New domain surfaces extend the existing human/Agent experience; they do not invent replacement shells unless explicitly authorised.
2. **One subject across apertures.** Desktop, terminal, Expression, Technē, Wiki, SharedField and Agent views preserve canonical identity where they represent the same thing.
3. **One central proving campaign.** C0–C5 receives the capability tracks. Native owner tests retain their own scope.
4. **No reopening returned carriers by default.** SF0–SF6 and EX0–EX6 are consumed as accepted floors; reopen only a concrete defect against their contract.
5. **No fake H gates.** Human Recognition closes mature lived claims, not intermediate construction phases.
6. **No duplicated orchestration.** Vāk/Resolve + C′ composition + Ta-Onta inhabitation already supply the semantic execution grammar; Factory is its developmental performance body, not a rival language.
7. **No issue-list orientation.** Open issues are work records. The person's activity and the UX/source relation determine what matters now.
8. **Returned reality can revise design, but explicitly.** If repeated lived evidence pressures an authored position, return a proposal to its authority. Do not let implementation or optimisation silently become product meaning.
