These are the established semantic offices in Central's `docs/DEVELOPMENT-FIELD-SOURCE.md`. They do not rename the claim-standing ladder, force six files, assign a QL shape, or declare every item in this folder tier 1. The same file can carry differently sourced claims and more than one role.

Native `ux_ref` binding requires the owner-issued human-authored/adopted source relation; putting generated prose under a vision path or setting a JSON field does not supply that event. Use Central's identity/provenance/scope/revision/privacy/source-lifecycle contracts and AIKit's existing [Project reflection and documentation operations, §§15–18](https://github.com/EpiLogos/ai-kit/blob/main/docs/v2/21-PROJECT-REFLECTION-AND-LOCAL-ARTICULATION.md). The actual cycle is:

```text
recover original intention and story
  -> identify native source/unit/row and current standing/revision
  -> bind the required capability, practice and context
  -> disclose the smallest sufficient selected material
  -> exercise the native operation through the intended Surface
  -> retain actual evidence, refusal or unresolved outcome
  -> assess which source, capability, practice, code or design is pressured
  -> reconcile that owner-owned material under the appropriate authority
  -> invalidate/rebuild dependent readings and repeat the affected story
```

For documentation population: inventory selected ordinary notes, HTML whole/units, matrix records and permitted Run/NOW passages; resolve explicit links with unresolved targets retained; create only the needed attributable Wiki reading; validate/persist through the actual owner; test search, exact read, relations, routes, frames, sources, Explain and History. Do not copy HTML/CSV to Markdown to conceal a missing adapter. An ordinary source remains ordinary and partial wholes retain their real grain.

For a coordinated account/capability edit: preserve exact source bases and unknown fields, choose the edit direction deliberately, review the changed meaning, validate companions before replacement and retain a recovery receipt for partial writes. Hash agreement records bytes/review basis, not semantic agreement. One atomic Wiki write does not imply atomic multi-document mutation.

For retirement: **assess → consolidate → reconcile → retire in place → archive/restore when requested**. Every selected unit is retained, transferred, superseded, conflicting or unresolved against a real successor. Preserve original bytes, exact historical access and inbound links. Deletion remains separately scoped. A proposal or copied archive is not a claim that the native retirement operation ran.

Use the current native command/Action schemas and returned SourceRefs rather than spelling a new `document.*` API in this plan. The source contract's historical implementation table is not today's runtime truth: inspect the current owner before marking HTML/CSV/UX reading, multi-source recovery or retirement supported. Missing operations are named owner work; the supported source-reading/bootstrap path remains usable with its actual limits.

## 4. Terminal and gateway proof must reach the real event

A terminal episode records the distinct **machine/service → terminal host → working-environment provider → pane/workspace Surface → SessionSpace/session → Agent/authority → direct or commissioned task** relations that actually exist. There is no requirement to instantiate every layer for a simple local task. Herdr, tmux and cmux remain separate provider specimens; the original mixed-world test is simultaneous.

A gateway episode records **sender/chat/thread → connector admission → gateway event → native recipient/context/practice → actual harness/model/tool → attributable result → outbound operation → actual Telegram message → later continuation**. Journal append and HTTP success prove only their bounded steps. Test real text/source-dependent work first, then group/privacy, multi-agent handoff, permission/cancel, media, replay/restart, private remote hosting, SDK/A2A and withdrawal.

Telegram provider grounding: [Bot API](https://core.telegram.org/bots/api) and [Bots FAQ](https://core.telegram.org/bots/faq), consulted 2026-09-13. Record the version/features supported by the tested connector, not a generic claim to all current API features. Use its supported update transport; respect platform privacy and delivery limits. Keep tokens and bot-token request URLs out of published evidence. The plan's duplicate/replay/rate-limit/failure probes are test elaborations over #154's promised connector, not claims of exactly-once platform delivery.

Use a dedicated authorised bot/chat and synthetic or explicitly selected material. Real Telegram traffic, model spend, private network changes and host restart have separate episode grants. Fixture transport, native agent execution, real Telegram delivery, physical service persistence and human experience retain separate proof. An absent credential/client/machine blocks only the corresponding branch; a missing native dispatch implementation is repair work, not missing hardware.

## 5. Returned evidence renews the right source

Each attempt attaches to the exact story/variant, operation/capability, context/Skill revision, software cut, provider and material situation. Failed attempts remain failed as observed; a later repaired attempt has a new basis. Preserve evidence outside cleanup targets and redact confidential material without losing causal references.

Use the existing D/C/P/M/H law. A computer-use Agent can produce genuine observed interaction evidence; it cannot author the person's EX or ratify vision. A source contract test cannot claim provider or physical use. Review the actual artifacts and result, not a worker's success statement. The native receipt shape is retained rather than copied into a new global results database.

A failure can pressure a description, context route, SDK contract, implementation, test expectation, design or intended experience. The diagnosis remains inference until supported. Repair at the actual owner under existing authority; only a genuine authored/design choice comes back to the person. Revalidate dependent stories after source/contract/practice change; preserve historical evidence against its old basis.

After the round, return one useful account of what the person can do, what remains broken or undecided, what changed, the evidence and the next ready activity. This source and its matrix reading remain live project documentation maintained through the same operation loop they describe.
