## 1. The experience being recovered

The person should be able to say, during ordinary work, “I feel like this didn’t go so well”, “this governance law is being misinterpreted”, or “agents seem to be using x as a reason for y”. The system should locate the relevant work and its actual conditions, show the evidence, help distinguish the kind of discrepancy, and carry an authorised refinement back into the running world.

The governing relation is one continuous movement:

```text
human purpose / Day intent / authored Ground
        ↓ situated for particular work
bounded child NOW + applicable source and praxis
        ↓ resolved and actually made operative
Agency + ContextResolution + body/session + material placement
        ↓ performed
Activity + explicit working records + changed material + verification
        ↓ returned against the originating purpose
human response + attributable comparison + unresolved difference
        ↓ where warranted and authorised
knowledge / praxis proposal / native repair / authored-source proposal
        ↓ verification and Recognition at their actual owners
renewed conditions → another real act in the same inhabited world
```

This joins existing Central context/source and temporal law, AIKit operative composition, Actuation actuality, Workcell material evidence and Factory Return. Factory #222 already explicitly requires reconstruction from intended difference and operative conditions through task execution, Day/NOW, Knowledge, archive and regression learning. The development objective is to make that relation ordinary to the person and Agents, not merely available in separate source files.

### Paradigm is inspectable mediation, not another context blob

The useful paradigmatic question is not only “what answer did the model produce?” It is “through what interpretation of purpose, world, source, practice and authority did this work become intelligible and actionable to this Agent?”

Central's existing Project Context Protocol supplies Ground → World → Praxis → Intent → Context Frame → Return. These are relations, not mandatory directories or an instruction to insert every source into every prompt. In the user's Epi-Logos world, QL-MEF supplies its own native organisation and reflexive readings of this field. The generic O:I relation remains operable without requiring QL fields or an Epi-only Agent.

For a consequential act, keep distinguishable: what the person intended; what applicable governance says; what context was selected; what actually became operative; what the Agent explicitly reported as its understanding; what it did; what returned; and what the person recognised. This is how the pattern of disclosure can itself become an object of inquiry without replacing authored intent with the system's interpretation.

## 2. Day, Workcell NOW and bounded work

[WORKCELL-NOW-TEMPORAL-FIELD.md](WORKCELL-NOW-TEMPORAL-FIELD.md) remains the temporal authority. In the first personal world, the primary workstation and Omarchy each have a persistent Workcell-root NOW. Several bounded child NOWs can coexist under either root. One Central-owned personal Day composes eligible relations from both by reference.

Central remains the root meta-project. A child software Project is not required to legitimate root work, a root Agent or personal Day inquiry. A Workcell-root NOW is a temporal/material anchor, not a new filesystem root or replacement for Central.

A bounded work occasion is not necessarily a model turn, a whole conversation, a single calendar date or a Factory Run. It can span several turns and Days; one Run can involve simultaneous children on both machines. Attempts retain their own effective conditions. The stable work relation and its changing execution conditions must both remain recoverable.

The person can read the field from My NOW, Workcell, Project, Journey/Run, Agent or an explicitly projected SharedField vantage. These are views over native relations, not copied tasks. The same Activity appearing in several views must not be counted several times.

**The Day is a human vantage, not an automatic scheduler or global permission grant.** Its writing and intentions can orient related tasks without silently issuing Commissions, marking personal tasks complete or granting every child access to every other child. Human intent evolves through actual source revision or accepted proposal. A result does not retroactively determine what the person must have intended.

Day rollover preserves live roots and children, pending permissions, uncertain effects and unreceived Returns. An Omarchy act received after the primary returns retains its original occurrence, work, source and Day relations. Receipt/review time remains separately visible. Archive and compaction preserve required evidence and continuation; a summary does not replace the exact basis still needed for inquiry.

## 3. The attributable learning corpus

“Corpus” here means a bounded, queryable composition of existing source, NOW, Activity, Knowledge, Thought and Return records. “Episode” below is ordinary descriptive language, not a proposed new canonical entity. No product acquires another owner's records merely to support this reading.

For each selected work occasion, the joined reading must be able to recover the following, or state precisely which evidence is unavailable:

| Relation | Required recoverable content |
|---|---|
| Purpose and scope | Human/source statement and revision or selected passage; bounded task purpose; relationship to Day and containing Project/World; expected outcome and verification; original versus subsequently revised intent |
| Temporal/material address | Workcell, root NOW and child NOW; parent relation where real; occurrence and observation times; original native cursors; Day and optional Factory/Routine correlations |
| Operative constitution | Actual Agency/AgentSession/SessionSpace; effective context and praxis basis; governing source revisions; selected model/harness/provider; authority and permitted effects; requested versus observed placement |
| Disclosure and activation | Eligible, selected, retrieved, projected, harness-native activated and confirmed-effective states; loader/scope and precedence owner; observation versus adapter inference; conflicts, exclusions and unknowns |
| Performance and retained account | Native Activity/tool/process/permission/effect records; attributable explicit plans, findings, claimed warrants and T/T′ where present; attempts, interruption, failure and late results |
| Returned reality | Exact output and Git/content comparison basis; checks and their tested revision; Claims/Evidence/Candidates; human response; open obligations; Return, Recognition and continuation |
| Use and cost | Provider-reported or derived usage with provenance, intervals and coverage; active/waiting time where established; retries and resource observations; unavailable is not zero |

A resolved source bundle must be attributable to the act that used it. Displaying today's Profile or freshly recomputing ContextResolution does not establish yesterday's effective context. Preserve the historical receipt or source-qualified binding through the existing owner mechanism; investigate the current native persistence/read seam before adding any field. Do not invent an opaque resolution identifier in the UI.

Central's source law remains load-bearing: **source role != source authority != disclosure/activation != runtime precedence**. A governance file may be materially loaded by a harness without having been selected by AIKit or recognised as human-authored. A generated projection is not proof of loading. A loaded instruction is not proof that its intended interpretation was followed. An advisory instruction is not observed enforcement.

### What makes this useful learning evidence

The strength of this corpus is its connection to bounded intentions and actual conditions, not a promise that everything recorded is correct. An Agent's stated reason is evidence of what it stated; a diagnosis of why it acted remains an inference unless supported independently. Explicit T/T′ and Run Thought can be compared with outputs, source changes and human feedback. Hidden model reasoning is not required.

Retain failed, interrupted and rejected attempts alongside successful ones. Queries retain scope, source revisions, selection criteria and coverage limits. A pattern drawn only from reported failures must not masquerade as the frequency of that pattern across all work. Similar text across different worlds or governance revisions does not establish the same operative condition.

Use normal AIKit Knowledge/source/query paths and Factory's existing developmental readings. Indexing, deterministic correlation and deduplication do not require a model call for every event. Interpretation can be explicitly requested or conducted under an already-authorised bounded Routine. Neither Day rollover nor opening a panel starts reflective cognition by itself.

Private NOW/source/feedback material remains private unless deliberately included in an audience-scoped Projection. SharedField participation does not publish the learning corpus. Retrieval for an investigation remains permission-bounded, including when the investigator is a root or Product Guardian Agent.

## 4. Natural-language feedback becomes an inspectable inquiry

The ordinary conversation is the primary ingress. A source, Activity, task or result selection can supply an exact initial target through existing selection/composer and native Return/evidence mechanisms. The person need not fill an incident form or learn technical refs.

The interface shows the resolved subject and breadth in plain language, for example “Review this task”, “Review today's related work” or “Compare uses of this rule”. Ambiguous deixis is not permission to inspect the entire private world: propose the smallest plausible scope, show it, and resolve material uncertainty before consequential action. Broader investigation is an explicit expansion.

### “I feel like this didn’t go so well”

Preserve the person's statement as their response, not an automatically verified defect. Recover the relevant task/NOW, originating purpose and expected result, then present intended versus returned reality. Distinguish an unsuccessful result, excessive cost or repetition, unwanted interruption, missing context, a material/provider failure and a mistaken test expectation. The person can refine what mattered without the system rewriting the original record.

### “This governance law is being misinterpreted”

Open the exact rule/source revision beside the affected work. Establish applicability and standing, how it entered the actual body, the known precedence/conflict relation, and what the Agent explicitly claimed or did. Separate an unavailable rule, a selected-but-unloaded rule, a stale or competing native instruction, an interpretation contrary to the source, a missing enforcement operation, and genuine ambiguity in the law itself.

The returned comparison includes evidence for and against the diagnosis. An implementation or projection defect routes to its native owner. A proposed clarification of authored governance remains a visible source proposal under the actual adoption law; a complaint does not silently revoke or replace the rule.

### “Agents seem to be using x as a reason for y”

Search the permitted field for explicit claims and relevant effects, initially bounded by the selected Day/work/source revision. Compare concrete episodes with their task purpose, active context, harness and outcome. Include counterexamples, cases where x was present without y, and cases where activation or the reason is unknown. Correlation is useful evidence but is not by itself causal proof.

The person should receive a readable source-linked finding and a proposed next step: retain an observation, test a hypothesis, revise an agent-owned practice, propose governance clarification, or commission native repair. Do not manufacture certainty or demand that every concern immediately becomes a Factory Run.

### The review surface

A substantial finding is ordinary returned material using the adopted shared report/verification/handoff family. It contains the human concern, selected work/corpus scope, intended and actual conditions, representative evidence and counterevidence, diagnosis and uncertainty, suggested native owner, and the next permitted operation. Evidence rows open their original NOW/session/source/artifact basis.

Selection, investigation, Commission, code/source revision, Recognition, Git integration, installation and personal Day inclusion remain distinguishable acts. Preserve the original failed occasion while testing the changed conditions.

## 5. One agent-context experience across the desktop

[FACTORY-AGENCY.md](FACTORY-AGENCY.md) remains the adopted spatial contract. This clarification specifies its contextual content; it does not replace its arrangement.

### Selection is not the context that carried the act

The panel needs two separately legible relations:

- **What I am looking at:** current source, selection, artifact, scene or Run, with its revision and unsaved state.
- **What this Agent was working from:** selected task/act and its actual purpose, temporal address, context/authority/body basis and Return.

Moving to another file changes the first relation. It does not silently change the session, disclose that file, replace historical context or redirect a pending message. The person can explicitly inspect another act, hold a historical reading, return to live work, or compose a new request.

### Ordinary right-hand companion

Retain Conversation / Activity / Context / Inspect and one transcript/composer.

**Conversation** carries the human relationship, addressed contributions, ordinary feedback, questions and supported permission/interrupt interactions. A compact work strip gives task purpose and a readable place/continuation state. It opens the same native task/NOW rather than a duplicate desktop record.

**Activity** presents stable native operations and resulting material, with exact act/task links. Expand a row into its source evidence, permission, tool/process result or original working Surface. Separate queued, working, waiting, uncertain, failed, returned and independently verified/recognised conditions according to what the owner actually supplies. A provider turn returning is not task success.

**Context** presents the relevant purpose, Ground/current-world sources, governance and praxis, actual disclosure/activation, bounds, and expected/actual Return. Start with readable source names and concise distinctions; exact refs, source passages, revisions, loader and precedence evidence are expandable depth. The sixfold may organise the reading without imposing six permanent forms or a full source dump.

For each relevant source or Skill, distinguish available, selected, projected, confirmed effective, excluded/blocked and unavailable evidence. Where activation is only inferred from adapter semantics, label that strength rather than displaying an unqualified “loaded” badge. Show the temporal basis of the reading and changes since the act; a refresh of available sources must not rewrite a held historical receipt.

**Inspect** supplies effective Agent/session/model/harness/environment/Workcell/authority details, exact native working-Surface access and current supported actions. Requested settings and actual observed state remain separate. Explain whether a change applies to a future turn, reconnect or a new session. Closing a view, interrupting a turn, cancelling delegated work and stopping material are separate controls.

A compact “Discuss this” affordance can compose the selected rule, event or result into the existing conversation with its provenance. It must not send automatically, replace the human draft, or create a second feedback/session store.

### Factory, Run and Observatory

In Factory, the centre remains conversation, Run Map/Live/Trajectory/Thought or the exact working Surface; the right displays the selected actual artifact body. Do not restore a permanently occupying AgentLayer that displaces returned work. Context depth remains reachable through the same conversation/Inspect/Observatory and normal explicit placement controls.

Run inspection connects intended work to the exact unit/attempt, child NOW, Agency/session/material and evidence. Selecting a failed operation or Candidate can open its contextual basis and comparison report. Candidate comparison retains alternative outputs, contradictory checks, independent verifier lineage and real Git/worktree basis; it is not a leaderboard.

The footer quietly aggregates current agency and attention across the selected vantage. It opens the exact task/session/permission/Return. Background progress or new findings do not steal focus, overwrite an unsent draft or replace the revision under review. Observatory offers deeper views over the same bindings, not another session identity.

### Day and field-level reading

Personal/Today presents the person's Day and its eligible current/returned work across both machines. Work can be grouped by human intent, Project, Agent, Journey or Workcell without changing its identity. Pending decisions are visible without turning all Activity into Inbox. Opening a task reaches its conversation, NOW, execution and returned material; opening a concern reaches the original statement and its investigation.

The same permitted state and native operations must be available to structured Agents, CLI/TUI and Gateway consumers. Human presentation can be quiet while agent readback is sufficiently complete. Neither surface may require scraping another surface to recover a context receipt.

## 8. One proving movement inside #65

The current inhabited orientation already says harmonise → inhabit → perform one real self-hosted change → turn remaining #65 discrepancies into ordinary Factory work. Do not postpone that threshold until every richer Epi instrument or publication scene is complete. The richer Nara/Epii experience can consume this same return grammar; it is not a prerequisite for generic feedback and self-hosting.

**C0 — bind meaning to operations.** Select one genuinely useful bounded task from the current development world, its original intended experience, applicable governance and proof obligation. Identify the exact task/NOW/context/Activity/Return reads and real gap to repair. Maintain wider coverage without spending the entire round on a census.

**C1 — prepare the actual world.** Reconcile the selected source/build/install/running/practice cut on the primary machine and Omarchy as applicable. Protect live work and private human source. Use bounded actor, witness and independent-verifier roles, finite effects/spend/retries and an explicit stop/recovery route. Preserve historical source and context basis before action.

**C2 — do useful work and receive a human concern.** Perform the task through a real admitted Agent. Observe actual context and native output, not only a projected instruction file. Make one of the ordinary feedback utterances against the task or a selected source/Activity. The person and investigator can both reach the same original evidence without manual transcript archaeology.

**C3 — pressure the joined field.** Across the selected round, exercise two scoped children, different context selections, repeated/late Returns, a changed governance revision, unavailable disclosure evidence, and view/host/Day changes. Include a task spanning a Day boundary and Omarchy activity while the primary is unavailable in the two-machine leg. Aggregate without duplicating events or leaking a sibling's private context. Keep original scope and source basis when broadening an inquiry.

**C4 — let the system carry repair.** Preserve the failed occasion, diagnose the actual boundary and commission a bounded native repair through Factory when development is required. Change implementation, source projection or agent-owned praxis at its proper owner. A proposed change to human intent/governance follows its separate Recognition boundary. Produce exact Candidate/artifact/test evidence and return a usable continuation, not a free-floating summary.

**C5 — experience the returned difference.** Rebuild/relaunch or rebind the changed component under the actual environment rules. Re-enter the same source story/task in the running world; preserve the original comparison while using a new, explicit evidence cut. An independent verifier repeats the affected activity. The person's own judgement supplies human EX/Recognition where required. A green test and successful Git integration do not substitute for this return.

Required negatives include: selected-but-not-loaded governance; unknown activation; conflicting or stale native instruction; wrong diagnosis; no correlation available; duplicate parent/child telemetry; a returned task whose outcome is still unsatisfactory; stale verification after editing; a proposed source change the person rejects; and a closed view whose work legitimately continues. These elaborate existing obligations rather than replace their source-defined coverage.

The first success is concrete: **a concern stated in ordinary use becomes a source- and task-grounded inquiry, an authorised improvement, and an independently checked difference encountered again in the same world.** Richer field-wide learning grows from accumulated occasions of that kind, not from a separate store of decontextualised transcripts.
