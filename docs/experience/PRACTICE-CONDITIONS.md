# Practices are selected for a situation

Read with [the story profile](STORY-PROFILE.md) and [local campaign](LOCAL-CAMPAIGN.md). The P-labels below are **document links**, not new Skill IDs, Agent roles, runtime permissions or a Method registry. They identify composable obligations in the existing repertoire. Each story states which of them is needed and what particulars determine the act.

## Common entry packet, supplied only within scope

For every acting participant establish: its actual identity and purpose; root/meta-Project or child scope; the human's current request; source and target revisions; declared allowed/forbidden effects; relevant existing decisions; selected material and exclusions; available tools/body; pending work; finite execution limits; and where another participant will find the outcome. Optional information is not loaded merely because it exists.

Do not send the verifier's expected answer, secret canary, exact hidden filename or private comparison source to the working actor. Missing context is a diagnosable state, not an invitation to inject the entire personal wiki. Explicit source selection, current policy and the declared task determine relevance together.

A stopped provider may require P11/P14 while an instruction conflict requires P03/P05. Both can occur within one story without changing its goal.

## Context determines the route at a handoff

Record the smallest source-qualified facts which select the next operation. Typical branches:

| Observation | Fitting response | Must not become |
|---|---|---|
| Source found, but excluded for this actor | Explain the allowed scope without leaking the source's contents; use available permitted material or ask an actual choice | Broader search that bypasses the exclusion |
| Procedure selected, but required tool unavailable | Preserve task and name the precise missing owner capability; repair or choose an explicitly permitted alternative | A Skill confidently describing a fake command |
| Native operation available, but current revision changed | Re-read/reconcile at source, retain original proposal and peer edit | Force overwrite or silent anchor relocation |
| Model/harness available, credential absent | Present the relevant native credential operation without exposing secrets; keep unrelated work usable | “Agent failed” or installing every credential provider |
| Remote service reports healthy locally, caller cannot reach it | Inspect the actual network/access path and correct it within scope | Public exposure as an undisclosed fallback |
| Child reported completion, artifact/check disagrees | Keep both report and contradiction; independent verification and accountable synthesis | Concatenation treated as verified work |
| Context limit approached or body replaced | Preserve admitted identity/source/obligations; use real provider support or explicit rehydration | New process described as magically remembering everything |
| Same failure after attempted repair | Stop that bounded loop, preserve evidence and escalate a precise remaining choice | Recursive subagents repairing their own test setup indefinitely |

## Practice changes are tested where they matter

A changed description needs realistic activation and near-miss trials; a changed body needs actual source/loading/application trials; a changed set needs membership, withholding and scope trials; a changed native contract needs current input/result and error-route trials. Preserve the original story and old failure before editing.

When code is missing, record its owner dependency rather than writing a Skill that advertises an unavailable operation. When the operation exists but the Agent repeatedly cannot discover or use it, that is a concrete Agent-UX defect in context, description, loading or feedback—not automatically another missing API. Mechanical permission and structure invariants stay executable, not polite prose.
