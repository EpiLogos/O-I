# Developer continuity — upgrade, failure, repair and re-entry

Use from the suite-operator Skill when the person asks to bring a development
suite current, reconcile failed integration, prepare an installed campaign, or
continue work after an upgrade. This is a reference procedure over existing
native operations, not another workflow engine or a new Skill/Method registry.
It implements [the everyday-loop walks](../../../docs/cradle/04-VERIFICATION.md#61-human-walk-arrive-and-understand-before-upgrading).

## Inputs and activation boundary

Required: the human's actual requested outcome; current World/root or child
Project; governing issue/Wayfinder and exact intended acceptance; accessible
source/installation; existing permissions; and the subject to return to.
For a developer full-suite campaign account for O:I, Central, Actuation, AIKit,
Factory, Workcell and QL-MEF. For an ordinary smaller World do not install all
seven merely to satisfy a checklist.

Read-only diagnosis, repository implementation and local installation are
separate operations. The person's request to investigate is not blanket authority
to rewrite shared Git history, adopt private rules, delete residue or restart
unrelated services. Existing authorised engineering does not require repeated
ceremonial confirmation. Ask only about an actual unresolved choice or effect.

## 0 — Recover the activity, not a convenient test

Read the original requested experience and the current issue/Wayfinder. Preserve
negative intent: no human dependency scheduling, repeated self-description,
private-source rewriting, silent fallback, or logs substituted for a useful
Return. Choose Teach / Do with / Do for as actually requested; no mode grants
power. Keep the intended Return place and current document/task.

For UX recovery, use authorial passages, issues/comments and canonical design,
not PRs as sources of intent. During an explicitly authorised code-convergence
operation, actual Git/PR changes are evidence of the work to integrate, not a
replacement for that intent.

## 1 — Establish the smallest sufficient current basis

Inspect native `oi products`, status/snapshot/verify and installed help where
available; use each product's own status/doctor/read contracts. `oi capabilities`
is a source catalogue, not proof of installed availability. Commands and required
arguments come from the actual selected version, never remembered examples.

Record source commit/tree, build input and artifact, registration/path/digest,
resident service/process version, effective Skill generation and observed
harness loading separately. Include companion executables and embedded desktop
inputs. A file on disk does not update a resident process; a symlink target does
not establish that an Agent loaded its new text. Keep secrets and private content
out of diagnostic output and shared receipts.

Use the exact current CAW readiness/joins ledger, not a new universal database.
Classify a mismatch as source/contract, build/install, process, context/Skill,
authority/provider, presentation or test. Show the first relation preventing the
requested act and what is still usable. Do not begin with another full-suite
census when a focused read establishes the next step.

## 2 — Carry the connective work

One connective session owns missing native code, consumer joins and E's tests
under O-I#220. Product ownership says where to fix code, not which chat the human
must reactivate. Preserve genuinely active writers; claim bounded disjoint work
or sequence it. Reuse accepted contracts and current native repositories.

For Git convergence, resolve the existing `central-git-convergence` and worktree
practices where available (Central#164). Preserve dirty/staged/untracked work and
unique commits; use isolated acceptance worktrees. Do not stash/reset/delete for
cosmetic cleanliness. Reconcile authorised dependent branches, squash/rebase
ancestry and merge order under repository review rules. Final evidence is from
the resulting accepted revisions, not earlier feature heads. An explicit
candidate cut is labelled candidate until accepted.

For Candidate-isolated tasks retain the same intended Project/repository,
Candidate, base/source revision, actual cwd, tests, diff, NOW and Return route.
A second worktree is not a second Project. Required environment/protection cannot
be silently weakened at dispatch or retry. Normal authorised source/build writes
remain distinct from NOW scratch. Comparison never mutates Candidates or implies
successful integration against a changed target.

## 3 — Prove the repository operation before claiming installation

Write and run native public-operation tests in disposable Worlds, temporary real
Git repositories, controlled clocks and protocol providers. Explicitly label
controlled model replies. Use available execution or ordinary GitHub Actions;
missing chat tooling is not a compiler-transfer project. Keep essential missing
code/checks pending, but continue unrelated implementable work.

Inspect the actual declared native install/build/test operations in
`docs/INSTALL.md`, `docs/CONVERGENCE-AND-ACCEPTANCE.md` and current product
descriptors. Prepare one coherent source cut and one runnable local handoff,
including actual prerequisites, pending local evidence and a recovery route.
Do not call missing production code a local-test obligation. Isolate target/build
outputs by worktree or serialise builds; changed source must reach the tested
executable. Retain disconnected-producer negative tests in the existing campaign.

## 4 — Install, fail safely, repair and resume

This step requires the actual local harness/Workcell and relevant authority.
Verify the selected cut, original work and rollback/precondition state. Execute
the owner installation/registration operations, verify native dispatch and safely
replace or retain active services on their real version. Apply only the exact
reviewed reversible Central migration and explicitly adopted private policy.
No remote source receipt certifies these effects.

Freeze the campaign cut. If repair changes it, record a new cut and rerun affected
checks. Do not continuously chase new main commits mid-campaign. Use finite
repair/retry scope and the actual native operation; no generic repair shell or
permission escalation. Unknown partial effects must be reconciled before retry.

Test refusal, interruption and recovery using an approved disposable specimen.
Keep unaffected writing available. Preserve source, drafts, pending messages,
permissions and Returns. Restore or explicitly rehydrate the same permitted
context; do not label a fresh session as native resume. A code rollback does
not claim to undo irreversible data effects or safely downgrade a newer schema.

## 5 — Return to the person's work

Return plainly: what changed; what remains usable; what failed or is unresolved;
what the person needs to decide; and how to inspect exact evidence. Retain the
selected task/document and original receiving destination. Delivery, inclusion,
acknowledgement, personal task completion and Recognition remain separate.

Use Central's existing ledger and archive practices for compact operational
pointers. The budgets in `central-ledger` apply to those records, not to the
person's writing, substantive plans or the necessary investigation. Do not
summarise away uncertainty, denied authority, failure or an unfinished obligation.

Independent full-feature verification is a fresh session/subagent, not the
implementer's confidence. Use 04 §6.1–6.6 and the existing CAW P01–P28 plus named
subcases. The human assesses intelligibility and room to work. Only the required
complete proof can warrant **usable end-to-end feature.** Otherwise leave one
precise next action for the same connective session, not an A–E relay assignment.

## Bounded bootstrap when the system cannot yet carry itself

- **No usable installed front door:** operate on the readable native repository
  and its verified commands in the coding environment. Record that this is source
  work, not installed use. A genuinely unreadable source is a specific access
  failure; one focused alternate read is preferable to an unbounded search loop.
- **Missing Skill discovery/loading:** explicitly read the exact authorised
  canonical Skill as a temporary input; record source/digest, reason, scope and
  replacement condition. This does not claim automated discovery. Reuse the
  existing local repertoire, do not copy it into another product.
- **First-time harness link missing:** follow the reviewed owned-link operation
  already described under AIKit#299 only where its actual native configuration
  and authority are established. Preserve foreign files and reversal. An absent
  Actuation descriptor cannot be replaced by invented harness facts. Upgrade
  closure must test a new Skill, a changed Skill, retirement and actual fresh-session
  use, not just an apply receipt.
- **Legacy temporal backend:** inspect its exact field format and permitted
  procedure under Central#164/#165. Do not run a legacy root mirror against a
  native CAW clearing or substitute derived Day readings for the human Day.
- **Human prerequisite genuinely missing:** return one exact source/adoption or
  environmental choice, keep its scope bounded, and continue independent safe
  work. This is not permission to normalise permanent manual orchestration.

Retire each bridge only after the native path demonstrates the same operation
and recovery. Preserve its provenance so the installed campaign can identify
where bootstrap work was used instead of hiding it as product success.
