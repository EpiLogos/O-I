# UX contract: the canvas is the place of work

The familiar actions are **place → shape → relate → animate → capture**. Underlying scope belongs to the shared Field, persistent Entities and Composition. The visible artifact hierarchy is Journey → named Scene → entities, spatial relationships, material, motion and optional page text.

The default screen is a living scene, not a control dashboard. It retains the supplied visual direction: restrained cream/ink surface, large O/I, crosshair, lower-left editorial text, small bottom transport. Editing opens beside the scene. The canvas never resizes merely because an inspector is opened. Presentation hides editing chrome while retaining the authored text.

## Context and ownership

**Scene** names the whole state, describes its character, sets duration/entry-transition time, edits page text and saves its view. **Objects** exposes stable entity centres, selection and the selected formation/pin. **Field** owns material, palette, global motion/physics and resonance. **Motion** opens the selected sequence, the shared two-phase instrument, travelling focus or automation. The scene strip handles journey ordering instead of pretending to be a particle-physics scrubber.

A pin is a pure force centre. A formation owns a particle allocation and can have local forces. Both are entities in the same medium. A chakra body is seven ordinary entities. A sequence belongs to its entity; a journey sequences whole scenes. Text is independently authored content and can be absent.

Spatial centres and station indices are separate. Camera view, working plane, layout plane and confinement are separate. Stored base values and evaluated automation are separate. A lock prevents editing, not motion. Undo reverses an edit, not elapsed simulation.

## Interaction contracts

Select/move, transient pointer interaction, persistent pin placement, formation placement, text manipulation and camera navigation are mutually intelligible tools. One pointer gesture has one owner. Do not apply pointer forces while using UI controls. Pin placement is a single deliberate click; the default returns to selection. Formation placement first chooses a glyph/shape, then plots its centre. A visible working plane establishes depth and supports grid snapping.

Centre markers and the object list make diffuse formations selectable. A selected influence shows its characteristic falloff; overlap is meaningful shared-medium behaviour. Ordinary dragging preserves depth; exact xyz and nudging remain available. Shift-selection permits arranging a subset. Layouts change positions without replacing entities or losing their sequences.

Glyph/text fields are drafts: typing must not fire global shortcuts or rebuild on every partial keystroke. Commit on Enter/blur; empty formation text has a defined fallback. Numeric controls retain a number-entry alternative. Unsupported physical controls remain explicit, not cosmetically “working.”

## Journeys and words

Each scene has an expressive name and character: Ink, Print, Gather, Between, Language, Weather, Quiet, Nocturne are starting examples, not locked modes. Scene duplication creates an editable variation. Names, composition, text, timing and view travel together in exported artifacts. “Living artifact” exports a self-contained HTML scene journey with its editor still inside.

Text layers have optional kicker/title/italic/body content, location, width, size, alignment and visibility. They can be moved on the canvas or numerically. Selection/editing hints are excluded from capture; text itself can be included. Safe escaping is required in every path, including import and standalone HTML export.

## Motion and inspection

Time-driven and morph-clock-driven sequences share one simulation time. Spatial keyframes are edited only in an explicit selected-link placement state. Base-entity movement moves the whole local path. The phase display exposes theta, phi and their evaluated relation. Travelling focus has an ordered route without changing centre locations.

Automation starts from the parameter's wave action. Lanes act on evaluated values; base values remain stable. The physical production engine must eventually expose its full driver ownership and blend order. A scene strip is not permission to claim instant physical seeking.

## Keep the result

“Save/export journey” is configuration. “Capture image” is pixels. “Record performance” is a moving capture. An exact runtime checkpoint is a separate future/native capability. Avoid the old ambiguous word “snapshot.”

The image/video output excludes chrome, guides and selection. Page text is optional. Video has fixed dimensions, detected encoder support, elapsed time and stop/review/save. Present recording limits and performance honestly. Changing aspect ratio is an explicitly described centre crop in this preview, not a silent recomposition.

## Remaining production UX work

True native physics/cymatics, full parameter-driver disclosure, existing schema-4 migration, runtime replay/checkpoints, offline high-resolution rendering and device-level recording benchmarks require the actual engine. Parameter favourites, a fully extended accessibility audit and native multi-touch camera gestures are not represented as finished merely because the core shell exists.

Scene duration in this shell is total scene occupancy, including its entry transition. Entity-sequence holds and transitions are separate durations. The preview's page dissolve is not a physical transition law.
