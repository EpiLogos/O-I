# Semantic Field acceptance

## Required gates

```sh
npm run lint
npm test
npm run build
npm run test:journeys
npm run test:gpu
npm run test:workspace
python field-studies-journeys/tests/semantic_field_browser.py
npm run test:browser
python field-studies-journeys/tests/module_browser.py
```

The final two served/media gates are authoritative in GitHub Actions when a local
browser policy blocks localhost or MediaRecorder completion.

## Architectural assertions

The unit suite proves that the physical resonator carries no chakra import or
chakra-coloured station object, modal affinity follows actual live mode energy,
entity reorder cannot retarget bindings, formation/pin forces compile through one
stable-ID contract, and colour only follows force radius when explicitly authored.

Schema tests prove v4 chakra identity migrates into v5 bindings without enabling
new colour, and explicit v5 semantic state round-trips.

Expressions model tests prove new semantic chakra starting compositions contain no
native entity `chakraId`/`stationIndex` authority and that bindings survive an
Expression round trip.

## GPU assertions

The native GPU suite covers attract, repel, vortex, spin, overlapping forces,
zero-step inspection, no-reseed transform edits, continuous resonance, clean
capture and projection. Its semantic case changes thousands of rendered pixels
while positions, velocities, simulation steps, seeds and target bakes remain
unchanged, proving semantic colour is render-only.

## Full-allocation combined case

`semantic_field_browser.py` runs the actual production adapter with:

- 62,000 particles;
- seven semantic chakra formation/force centres;
- two additional overlapping first-class pins;
- travelling focus;
- continuous resonator;
- semantic spatial colour;
- one live automation lane.

The test asserts the field advances, retains a single seed, evaluates seven colour
fields, reports focus/resonance and evaluates automation. It records software-WebGL
fps as evidence only; it does not invent a target-device performance guarantee.

## UI assertions

The workspace suite verifies semantic assignment is an explicit contextual edit,
does not mutate the selected entity's force/shape/tint, does not change GPU state,
and supports an independent colour radius. Disabling semantic expression leaves the
physical simulation unchanged.

Existing library, orbit, tool ownership, import/export, touch and narrow-layout
contracts remain mandatory.

## Compatibility

Legacy `SpatialChakraConfig`, `chakraId`, `stationIndex` and hard-coded chakra
cymatic profiles are compatibility/migration inputs, not new authoring authority.
The old React workbench remains retired reference material.
