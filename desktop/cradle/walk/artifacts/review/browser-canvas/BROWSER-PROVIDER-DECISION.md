# Browser provider decision — installed-source review, 2026-09-08

Standing: agent recommendation grounded in installed source. No browser implementation, live engine comparison or production edit performed here. Reviewed Tauri **2.11.5**, Wry **0.55.1**, tauri-build **2.6.3**, and the current cradle material/pane host. This is a staged engineering decision, not a new Workcell BrowserSession contract.

## Recommendation

Keep the contained material renderer for selected local HTML/documents. Prototype a genuine browser as a separate native webview contribution behind explicit host integration, starting with an isolated native window to establish navigation, profile and authority behaviour. Promote it into a canvas child only after overlay, focus, sizing and reparenting are demonstrated. Choose instrumented Chromium separately if Chrome compatibility or browser automation is a requirement; its control connection is not an embedded canvas renderer.

| Option | What the installed APIs support | Practical cost / limit |
|---|---|---|
| Native Tauri/Wry browser | Independent top-level document in the platform engine; navigation/new-window/download/page-load/title hooks; native bounds/focus/show/hide. On this Mac the body is WKWebView, not Chromium. | Child embedding requires Tauri's `unstable` feature. Native child stacking, permission UX, profile isolation and window/pane lifecycle require deliberate integration. |
| Instrumented Chromium | Real Chromium browser with persistent context/profile and automation via Playwright/CDP. | An external controlled browser is usable as an external native surface, but CDP does not insert its compositor into the Tauri canvas. A streamed/embedded solution introduces an additional transport/composition/input/accessibility problem. Do not label a screenshot stream or launch command a fully integrated browser. |
| Existing material iframe | Actual selected HTML and relative assets in the established contained material host. | It remains a scoped document renderer. It does not establish general browsing, login/profile continuity, tabs, downloads or browser permissions. Do not weaken its sandbox to simulate these capabilities. |

## Exact installed constraints

**Child embedding is explicitly unstable.** `Window::add_child` is compiled only under desktop plus feature `unstable`. Current cradle Cargo declares Tauri `features = []`. Wry `build_as_child` creates an NSView under the window content view on macOS, a child window on Windows, and has X11/Wayland distinctions on Linux. This is native view composition rather than an element inside the existing React DOM. [Tauri add_child](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/window/mod.rs:1126), [current dependency](/Users/admin/Central/Work/O-I/desktop/cradle/src-tauri/Cargo.toml), [Wry child construction](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/wry-0.55.1/src/lib.rs:1465).

**Reparenting exists but does not by itself prove tab continuity.** Tauri offers `set_bounds`, `set_focus`, `hide`, `show`, `close` and `reparent`. Without `unstable`, reparenting involving a normal WebviewWindow returns `CannotReparentWebviewWindow`. Even with that feature, moving the existing webview must be verified on the target OS; reconstructing from a URL is not equivalent to preserving document history, form state or an in-flight operation. Current cradle detach creates a new app renderer around the binding, which is appropriate to owner-backed editor views but cannot automatically preserve arbitrary live browser DOM state. [Tauri lifecycle/reparent](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/webview/mod.rs:1500), [current detached construction](/Users/admin/Central/Work/O-I/desktop/cradle/src-tauri/src/windows.rs).

**Profile lifetime must be explicit.** On WKWebView, Tauri documents `data_store_identifier` as the replacement for unavailable `data_directory`, available macOS 14+/iOS 17+. Incognito uses the nonPersistent store. A deliberately isolated browser profile must not silently reuse the shell's storage identifier. Persisting a profile is different from keeping a tab document alive; destroying/recreating the webview can lose transient state despite cookies surviving. Playwright's persistent context stores session data in `userDataDir`; its documentation warns against the person's ordinary Chrome profile and concurrent processes sharing one directory. [Tauri profile APIs](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/webview/mod.rs:988), [data-store identifier](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/webview/mod.rs:1080), [installed Playwright API](/Users/admin/Central/Work/O-I/desktop/cradle/node_modules/playwright-core/types/types.d.ts:17480).

**A native child needs a host overlay policy.** Do not assume CSS z-index makes the React command menu, sidebar drawer, drag preview or modal appear above a sibling native child. Position the child from actual pane bounds; update for splits, coarse/narrow chrome and scale-factor changes. Hide/restore it while a covering shell overlay is open unless a tested native overlay strategy is adopted. Inactive tabs must stop receiving input; full-view, tab moves and window detach must operate on the same registered browser view. `hide()` is a visibility operation, not an established suspension of scripts/media/network. Measure hidden-page activity and disposal separately. These are integration deductions from the native-child composition and lifecycle APIs, not claims of a tested defect. [Wry native composition](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/wry-0.55.1/src/lib.rs:1465), [Tauri hide/show/bounds](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/webview/mod.rs:1509).

**No-capability does not historically mean no local custom command.** Exact Tauri 2.11.5 IPC source checks ACL for plugin commands, when an app ACL manifest exists, or for a non-local origin. Consequently local application custom commands without an app manifest are not automatically gated just because a capabilities file omits them. Remote origins require explicit matching remote capability in this installed version. `AppManifest::commands` generates allow/deny permissions; register the entire command list and grant only trusted shell webviews. A browser child must have no wildcard shell window capability, no broad remote capability and no generic kernel invocation. Test every custom command from both the trusted shell and untrusted content. Tauri also installs its IPC initialization scripts into managed webviews, so relying on hiding a JavaScript global is not an authority boundary. Parent is independently implementing this command-manifest correction. [IPC enforcement](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/webview/mod.rs:1819), [manifest generator](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-build-2.6.3/src/acl.rs:93), [managed-webview initialization](/Users/admin/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/manager/webview.rs:156).

## Staged acceptance before choosing the in-canvas provider

1. **Finish local material parity:** actual HTML module/assets/MIME/CORS behaviour in the contained host, including suspend/dispose. Record this as material support, not browser completion.
2. **Prove one isolated real browser window:** explicit initial URL, navigation/back/forward/reload, redirect/popups, error recovery, downloads and permission disposition; separate profile choice; no kernel/custom-command access. Record actual engine and persistence behaviour.
3. **Prove the native canvas child:** enable and pin `unstable` deliberately; exercise split resize, tab switching, side drawers, command/search overlays, native focus, full/restore, move and detach/reparent/redock. Preserve a typed form and navigation history through the cycle. Do not ship replacement-URL reload as state preservation.
4. **Make the Chromium decision from needs and evidence:** if Chromium-specific compatibility/automation is needed, start with a deliberately owned external profile/process and existing actual provider operations. A CDP attachment controls Chromium only and is documented as lower fidelity than a native Playwright protocol connection. A canvas compositor or remote surface remains separate work. Do not invent an owner BrowserSession schema to paper over that missing integration. [installed CDP contract](/Users/admin/Central/Work/O-I/desktop/cradle/node_modules/playwright-core/types/types.d.ts:17317).
5. **Measure lifecycle after the feature tranche:** warm baseline and repeated real browser tab/window cycles; include renderer children, hidden media/activity and profile/process cleanup. Preserve the distinction between closing a consumer view and terminating an independently owned provider operation.

The useful immediate choice is native browser proof first, because the installed stack already provides the engine and native window. Embedded-child acceptance remains a deliberate follow-up; instrumented Chromium is an alternative provider requirement, not a shortcut through native pane integration.
