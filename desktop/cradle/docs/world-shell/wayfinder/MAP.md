**Standing laws the lanes inherit:**

- *Port law* — port, never recreate. Before writing any new module, name the
  legacy source it ports by path:line (cradle, expressions-app, kernel,
  Archetypal-Earth). Real refactor = port + retire in the same change; no
  dual maintenance, no parallel stores. For Archetypal-Earth: **actual code
  copying** — modules move verbatim first, hosts/bindings adapt after; no
  React rewrite; no Jung corpus in the port.
- *Aperture law* — native-actions adherence: every device and action uses
  declared owner operations (`boundary_op` named per action, kernelOp /
  frame host-commands / device change kinds), custody and receipts intact;
  a successful UI flag is never evidence of a native effect.
- *Widget law* — the mockups are guides, never ceilings. The agent-shell
  mockup and the world mockup's Revision 2-5 forms give each device its
  shared vocabulary: states (folded/compact/configure/deep), knob/slider/
  light semantics, tooltips, keyboard, empty and refusing states, and the
  waiting component forms capabilities plug into. A device is done when it
  works honestly through its owner AND functions and looks better than the
  mockup drew it — the mockups already hold a good standard, and the real
  feature is expected to exceed them. Where an implementation improves on
  the mockup, the improvement is recorded back into the guide; falling
  short of the guide is the only failure.
- *Musical law* — M1 is the oscillator source (D13); M2 modulates, never
  generates; sound and form are projections of one state (common cause);
  every sonic/physical role is classified (resonator ≠ emitter ≠ collision
  trigger ≠ analyser ≠ visual-only); the realtime boundary excludes
  allocation, blocking locks and UI work.
- *Honesty boundaries* — no audio/device-editing/performance claims before
  those owners land; Factory and Central entry points admitted through
  their owners' manifests; all 126 targets pending until each target's
  stated behavior is exercised; UI acceptance by direct computer use.
- *Craft law* — target sets name craft-quality bars, never compliance checklists: floors that measured churn passed 52/52 while
  the craft failed (buried glyphs, mandated metadata on the stage, no colour journey, no stillness, no fullscreen).
  (`campaign-evidence/2026-10-07-expression-audit/FINDINGS.md`)
- *Instrument law* — instrument work happens in the instrument; earlier enrichment lanes built UI and features outside the
  proper app. Harmonisation and integration land in the cradle through the env seats.
- *Reverse-engineering guardrails* — read-only on every product tree; no target code or assets move into a product tree
  (recovered material appears only as short quoted evidence with offsets, inside the campaign directory); no DRM circumvention,
  and no possession means no RE: record the candidate as blocked-with-reason; scratch (cloned checkouts, captures, fixtures)
  lives outside product trees; a completion claim carries executed evidence, and what stayed unverified is named.
