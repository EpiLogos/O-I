## 1. Archetypal-Earth module inventory

Host-wide facts that every module shares:

- **Language/runtime:** TypeScript, ESM, Vite 8 + `tsc --noEmit`; Vitest for
  tests. Vanilla TS throughout — no React (the design's "no React rewrite"
  port law is already satisfied by the found code).
- **Runtime dependencies actually imported in `src/`:** `three` (^0.186.1) and
  the d3 family (`d3-force`, `d3-quadtree`, `d3-selection`, `d3-zoom`,
  `d3-drag`). **`globe.gl` is declared in `package.json` but imported
  nowhere in `src/`** — a leftover dependency; a port does not need it.

  (index.html), loads `data/field.json` (required — failure message
  "The atlas data …"), `data/history.json` and `data/symbols.json` (optional,
  warned), builds the model, constructs `GlobeEngine(globeEl, model, time,
  callbacks, prefersReducedMotion)` then `Controller(model, engine, time, app,
  history)`. WebGL is required; the boot failure path says so plainly.
  Dev-only global `__earth` exposes `{engine, ctl, model, time}`.
- **Data expectations (paths only):** `public/data/field.json` (required),
  `history.json`, `symbols.json`, `sky.json` + `sky.ties.json` (sky scale),
  `images.json` + `public/img/{archetypes,families,occurrences}/*`
  (ImageRefs), `public/textures/earth-{2k,4k,8k}.jpg` (generated by
  `scripts/textures/prepare.mjs`). External live data: NASA GIBS tiles
  (CORS fetch, own terms) and Wikimedia Commons (images pipeline only,
  build-time).
