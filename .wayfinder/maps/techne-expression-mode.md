## 0. Owner clarification this Wayfinder locks

The previous preparatory UI used the six Technē instruments as visible tabs/host slots. That was a useful integration scaffold, not the final human experience.

The intended experienced product is now explicit:

```text
                    ONE EXPRESSIONS SYSTEM
                           one Stage
                           one subject
                           one selection
                           one world
                           one session
                              │
              ┌───────────────┴───────────────┐
              │                               │
       EXPRESSIONS MODE                  TECHNĒ MODE
        3:3 lived cut                     4:2 deep cut
        Nara / Anima                      Epii / Technē
        physics/material                  knowledge/work field
        expressive making                 investigative making
              │                               │
       existing Expressions             M0′–M5′ lenses
       authoring HUD                     inside one Technē HUD
```

Technē is therefore **the second full-screen operating mode of the existing Expressions system**.

It is not:

- six applications;
- six browser-like tabs;
- a launcher page around six independently mounted panes;
- another graph/store;
- a second Expression engine;
- a separate Research Canvas application;
- a set of "waiting for material" surfaces mounted before the shared subject is resolved.

Switching Expressions ↔ Technē changes the **HUD, available operations and mode of disclosure** around the same current field. It preserves native subject/source/selection/occasion/Expression/Scene/session identity wherever those facets exist.

The existing QL dual-reading architecture already requires this continuity. This Wayfinder determines the concrete final UI organisation.

# II — The Web: human-facing relational workspace

## 4. "Web" is a presentation/composition noun, not a new ontology

Use **Web** as the human-facing name for the Expression-backed relational workspace in Technē mode.

A Web is composed from existing identities:

```text
World / Project / ProjectCentral
        +
WikiSpace / WikiNode / WikiConstellation / WikiReading
        +
Expression / Profile / Scene / Edition
        +
TechneReading / DisclosureSession
```

No canonical `Web` semantic store is created merely to support the UI.

Useful human names:

- **Project Web** — the relational Expression of a selected Project/ProjectCentral;
- **Personal Web** — the person's independently grounded Central-rooted local O:I world;
- **O:I Web** — the public/shared experience over admitted projected worlds;
- **Epi-Logos Web/context** — curated philosophical world/profile over the same substrate when entered through the Epi-Logos entrance.

## 5. Project Web structure

For the first ordinary Project path:

```text
Project / ProjectCentral bounded whole
        ↓
one Project Web / Expression identity
        ↓
OVERVIEW SCENE
        contains the available Wiki constellations
        as addressable Expression objects/formations
        ↓
CONSTELLATION SCENES
        each scene presents one selected constellation/local whole
        ↓
Wiki nodes + exact typed relations
        represented as bound Expression entities/relations
```

The overview Scene is not a copied semantic graph. It is a presentation of the real current Wiki/Project reading.

A constellation object in the overview may use a canonical QL shape/form where warranted. Entering it moves to the corresponding constellation Scene while preserving the same native constellation identity.

A single WikiNode may itself be a local whole. The existing AIKit Wiki relation is already recursive:

```text
WikiSpace
  → WikiConstellation / structural whole
      → WikiNode
          → node-as-local-whole / 0/1 anchor
```

A presented one-fold `0/1` may therefore stand as the compact face of a disclosed two-/three-/larger-fold basis while retaining that basis through ShapeBinding/derivation. Expanding it changes disclosure, not identity.

## 6. QL geometry is a warranted presentation grammar

Reuse the actual QL shape system:

- `QlShape`;
- `StructuralConstellation`;
- `ShapeBinding`;
- canonical 1/2/3/4/5/6/7…12 fold forms;
- 4×4, 4×4×4, 6×6, relational sixfold, 18-fold, 10×10 where genuinely warranted;
- canonical shape/address/derivation refs.

Hard law:

```text
QL shape / address
    = structural or presentational warrant

Wiki relation
    = source-owned semantic relation
```

QL geometry never manufactures semantic Wiki edges. The executable contract already states that a shape address does not assert semantic relation.

Use the QL shape to generate the appropriate Expression formation/layout/glyph treatment for the constellation while retaining exact Wiki refs.

## 8. Two Library presentations

Keep both presentations of the same collection data:

### A. BROWSE / LOCATION — columnar Web inventory

This is the normal Technē Library view.

Group by current World / Central / ProjectCentral / collection.

Each Web/Expression row should show:

```text

[ source/world/project identity ]
```

# VII — Stop the "waiting for material" failure

## 20. Resolve once, lens many

The current final UX must not mount six instrument panes which each separately appear to wait for data.

The mode controller should resolve the current field once:

```text
current World/Project/subject
        ↓
Wiki / ProjectMap / Search / source readings
        ↓
bounded local whole
        ↓
TechneReading
        ↓
DisclosureSession
        ↓
active lens component
```

All instruments consume this one current reading/session.

Switching lens does not re-identify the subject or create a new source load.

If a reading changes, the controller updates the shared reading and the active lens.

## 21. Distinguish four states

Never collapse these:

```text
NO SUBJECT
    nothing selected yet

LOADING READING
    native owner request actually in flight

READING RESOLVED / LENS UNAVAILABLE
    subject exists, but required facet is absent
    show reason immediately

READING RESOLVED / LENS AVAILABLE
    mount instrument immediately
```

A registered instrument component must not show a generic "waiting" state when the current `TechneReading` already contains the material it needs.

Fix adapter/host propagation where this occurs.

## 22. Active-only renderer lifecycle

Only the active rich lens renderer should allocate expensive resources.

```text
active lens renderer        allocated
inactive rich renderer      suspended/unmounted
Expression physics body     active where the current mode/scene requires it
same live object elsewhere  subscribed/reused, not duplicated
```

Technē is not permission to run graph + SVG Canvas + Timeline + globe + particle field + Palace simultaneously behind six hidden tabs.
