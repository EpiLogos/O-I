# AIKit product-fidelity review — 19 September 2026

**Report only. Primary owner: `EpiLogos/ai-kit`. Finding prefix: AI.**

## 1. Intended experience, authority and scope

AIKit's product is not merely a catalogue, a folder of Skills, or a launcher. It makes the relevant part of an existing person's World discoverable, explainable and usable by an actor in a particular Project and act. The mature relation is:

```text
permitted source and current context
  → discovery / typed resolution / explanation
  → selected practice, tools, body and model
  → target-native projection and actual activation
  → useful, authorised execution
  → attributable History / Return / subsequent use
```

An existing harness is a legitimate entrance. So is an O:I-created SessionSpace. Neither requires the person to reconstruct the suite's ownership graph, abandon an existing configuration, install every optional product, or learn philosophical operators before doing ordinary work. Central remains the root meta-Project and source/temporal owner; Actuation supplies Agency, execution authority and actual execution evidence; AIKit supplies situated resolution, practice and session composition; Workcell supplies material conditions; Factory owns commissioned development; O:I composes and presents their public operations. A retained external session must not acquire invented O:I/Factory ancestry.

## 4. Positive architecture to preserve

### 4.1 One situated faculty, not one monolithic authority

The [shared AIKit Service][service] and TUI application layer deliberately call the same core resolution and target adapters. The public command tree distinguishes typed resource search, Knowledge, Wiki authoring, runtime composition and native operation. Those are useful faces of one field, not automatically competing search engines. The relevant question is whether a request lowers into the same typed source/owner interpretation and preserves explicit scope. The knowledge-fitness structural `Scope` repair is therefore a gain, not an invitation to add another flag parser.

Familiarity is an access aid, not trust, authority or fitness. The explicit knowledge-open operation is an appropriate place to record successful use; merely rendering or refreshing a search should not manufacture it. Read-model copies carrying exact owner refs and revisions are legitimate projections. Reimplementing foreign semantic authority or treating a cached copy as source is not.

### 4.2 Central sources remain sources

Central's [file-map operation][central-map] and AIKit's [adapter][central-adapter] retain source identity, root/Project scope, standing and retrieval exclusions. AIKit's Skill snapshot checks and source promotion validate the actual source tree rather than trusting a receipt-shaped string. Bounds and path protections matter. A current Skill snapshot can appropriately be required before projecting that Skill. AI-002 asks to isolate unrelated operations, not to weaken freshness or permission checks.

The knowledge materialisation path does not establish its truth by filling a second store with authoritative Central source bodies: source references remain owner-backed and actual bodies can be retrieved through the native aperture. The report's performance concern is invalidation and reconstruction of derived knowledge, not a claim that every read pastes the entire Central into a prompt.

### 4.3 Practice retains purpose, source, trust and target timing

The Method implementation recognises the `METHOD:` description on the same Skill. Sets and Profiles select/combine practice without minting Agency. Additive usage overlays are not replacement canonical Skill bodies. A changed source revision may need new review before it can project; retaining that refusal is correct even when the old version was trusted.

Target adapters and the admission SDK preserve edition-specific faculties. A projected file is not proof of native loading. The baseline contains real recent repairs: hook stdout injection, broker/shared-tree handling, and the Pi carrier. These deserve source credit; they do not establish that a still-running older target session loaded the change. Owned projection cleanup should remain distinguishable from deleting user-authored configuration.

### 4.4 Native model selection is not silently replaced by a convenient route

The [resident model path][model-resident] and [model-policy implementation][encounter-model] bind explicit model/provider policy to native session identity and source constraints. The examined Pi path checks provider/model, source basis, permitted invocation and credential reference instead of silently widening to ambient credentials. That is the right shape for preventing shadow model routing. It is not an audit of every possible provider adapter.

The [encounter owner][encounter-service] records native model configuration requests and confirmations separately. Its response can say `selected: true` while retaining `inference_observed: false`. A provider-confirmed change followed by receipt-persistence failure is explicitly uncertain and warns against automatic resend. Prompt acceptance likewise is not completion or useful result. These distinctions must survive the O:I controls.

### 4.5 Sessions, material NOW and development are different relations

A SessionSpace's environment binding and a provider's native session are not interchangeable IDs. Herdr operations are already routed through the public working-environment field, alongside the relevant tmux/cmux facilities; an older “tmux/cmux only” diagnosis would be false at this baseline. Reconciliation preserves human-created work rather than assuming every extra pane is drift to delete.

Central's material root/child NOW and human Day obligations remain owned there. AIKit can bind work and continuation to those relations; it does not obtain authority to close a Day by closing a pane, stopping a resident, or ending a task. The [task execution boundary][encounter-task] rechecks Agency and material/source constraints; Workcell supplies actual execution isolation. Factory's native adapter preserves Commission and developmental identities and does not relabel an ordinary direct agent session as a Factory Run.

### 4.6 Actuality already has an owner

Actuation's [realised-actuation contract][realised] rejects inert model availability as realised acting, and requires evidence for an observed claim. Its [StreamRuntimeObserver][stream-observer] preserves actual supplied loop callbacks, checks the Actuation identity, appends under the native stream cursor law, and only then returns an evidence reference. The opaque runtime `run_id` is expressly not a Factory RunRef. This is valid architecture to use, not replace in a desktop JSON parser.

That particular observer leaves `model_usage` absent; it cannot alone prove which configured model actually inferred or what it cost. This says nothing about other provider-native observation ports not inspected here. AI-005 concerns a broken consumer join, not an absence of all Actuation execution machinery.

### 4.7 Some transport paths are already bounded

The encounter service has private socket permissions, one resident owner per home, a 32-client limit, bounded request/response sizes and read/write deadlines; completed worker handles are retired. The task boundary and Workcell stdio path also have explicit bounds. AI-003 is deliberately narrower: unbounded short-lived subprocess queries and output collection elsewhere must not be defended by these unrelated good implementations, nor should intentional resident lifetimes be treated as defective merely for being long-lived.

## 6. Findings

Priority is relative to the affected activity, not an arbitrary health score. Confidence in a static mismatch is separate from the unmeasured frequency or severity of its runtime manifestation.

### AI-001 — SessionSpace delivery/dispatch does not compose across the published cuts

**Activity and authority.** O:I-started or resumed sessions, existing-harness adoption that needs native SessionSpace operations, and managed current-cut installation. Existing owners: AIKit #114; O:I #268, #376 and its existing dispatch/install work. The required relation is the actual shipped protocol reaching the caller, not merely a successful primary-binary installation.

**Positive / negative requirement.** Preserve native AIKit session ownership, explicit executable authority and receipt validation. The caller must use a protocol actually implemented by the selected artifact. Do not silently choose a stale PATH binary, rename `session` into the different SessionSpace protocol, or claim an unpushed local fold is in published main.

**Code and revision evidence.** At AIKit baseline, [Cargo/release][release] packages `aikit`, `aikit-session-space`, `aikit-explain-history` and `aikit-knowledge-living`; the [SessionSpace parser][session-bin] is in its companion. The O:I baseline [recorded installer][oi-installer], `install_manifest_product`, extracts an archive but copies only `artifact.entry`; its baseline [dispatcher][oi-route-baseline], `dispatch_session_space`, expects the companion beside the primary executable. This is a concrete gap for that installer path, not proof that every S0 artifact lacks companions.
